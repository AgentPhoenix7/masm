# Question 1 — hidden password verification

Source: [Q1.ASM](../Q1.ASM).

This program lets you practise keyboard input, counted strings, comparison,
conditional branches, and a small retry state machine. The explanation follows
the same approach as Assignment 1: start with the algorithm, then connect the
8086 instructions to ideas you already know from 8085.

The complete job is:

```text
Read an invisible password entry.
Compare its length and characters with "admin123".
If it matches, print "Access granted."
Otherwise consume one of three available attempts.
After the third failure, print "SYSTEM LOCKED." and terminate.
```

The source calls this a BIOS-like password system. It is a **DOS executable
simulating a password screen**. It does not replace the BIOS, run before DOS,
or lock the computer after the process ends.

---

## 1. Begin with the flow you should understand

```text
MAIN
  │
  ├─ initialize DS and ES
  ├─ display title
  │
  └─ TRY_AGAIN
       ├─ display prompt
       ├─ READ_PASSWORD
       ├─ CHECK_PASSWORD
       │
       ├─ match ────────────> ACCESS_GRANTED ──> EXIT_PROGRAM
       │
       └─ mismatch
            ├─ decrement ATTEMPTS
            ├─ zero ───────> SYSTEM_LOCKED ───> EXIT_PROGRAM
            └─ nonzero ────> print remaining count ──> TRY_AGAIN
```

There are two separate questions:

1. How do we collect a password without displaying the characters?
2. How do we decide whether those collected characters form the right password?

`READ_PASSWORD` answers the first. `CHECK_PASSWORD` answers the second.

---

## 2. The three segments

```asm
STACKSEG SEGMENT PARA STACK 'STACK'
    DW 128 DUP (?)
STACKSEG ENDS
```

`DW` reserves words. Each word is two bytes, so this reserves:

```text
128 × 2 = 256 stack bytes
```

`CALL`, `RET`, `PUSH`, interrupt entry, and interrupt return all rely on the
CPU stack. The DOS `.EXE` loader obtains initial `SS:SP` information from the
linked executable.

In 8085 you also need a valid stack for `CALL`, `RET`, and `PUSH`. The new idea
here is that the stack address uses a segment register and an offset.

```asm
DATASEG SEGMENT PARA PUBLIC 'DATA'
```

begins the variables and messages.

```asm
CODESEG SEGMENT PARA PUBLIC 'CODE'
```

begins the instructions.

`PARA` requests alignment on a 16-byte boundary. `PUBLIC` is a linker combine
attribute; it does not mean that the variables are shared with arbitrary DOS
processes.

---

## 3. Constants are different from variables

```asm
MAX_INPUT EQU 20
```

`EQU` gives the assembler a constant value. It does not create a memory byte
containing 20.

Compare:

```asm
INPUT_LEN DB 0
ATTEMPTS  DB 3
```

These declarations create actual memory bytes that instructions can change.

```text
MAX_INPUT → assembly-time constant
INPUT_LEN → mutable byte in DATASEG
ATTEMPTS  → mutable byte in DATASEG
```

This distinction is the same general distinction between an assembler symbol
and a byte declared with `DB` in 8085 source.

---

## 4. The password has an explicit length

```asm
PASSWORD     DB 'admin123'
PASSWORD_LEN EQU $ - PASSWORD
```

The stored bytes are:

```text
index       0  1  2  3  4  5  6  7
character   a  d  m  i  n  1  2  3
```

There is no terminating zero or terminating dollar sign after this declaration.

In the `EQU` expression, `$` means the assembler's current location. Therefore:

```text
current offset after eight bytes − starting offset = 8
```

So `PASSWORD_LEN` is assembled as 8.

The `$` inside a quoted screen message means a different thing: it is a stored
ASCII dollar character used by DOS service `09H` as a terminator.

---

## 5. The input buffer is not a DOS function 0AH buffer

```asm
INPUT_BUFFER DB MAX_INPUT DUP (0)
INPUT_LEN    DB 0
```

Here all 20 bytes of `INPUT_BUFFER` are character storage. There is no
maximum-length/count header at offsets 0 and 1.

The program collects keys itself using BIOS services, then stores the active
character count separately in `INPUT_LEN`.

For the entry `admin123`:

```text
INPUT_BUFFER[0..7] = 'a','d','m','i','n','1','2','3'
INPUT_LEN          = 8
```

Bytes outside `INPUT_LEN` are ignored. This is a **counted string**.

---

## 6. Messages use a different representation

```asm
PROMPT_MSG DB 'Enter password: $'
NEWLINE   DB 13,10,'$'
```

The prompt ends with `$` because `PRINT_STRING` uses DOS `INT 21H/AH=09H`.

`13,10` are carriage return and line feed. Together they produce the usual DOS
newline.

Keep these two data formats separate:

| Data | How its end is found |
| --- | --- |
| Password constant | `PASSWORD_LEN = 8` |
| Entered password | `INPUT_LEN` |
| Screen message | `$` character |

---

## 7. `ASSUME` does not load segment registers

```asm
ASSUME CS:CODESEG, DS:DATASEG, SS:STACKSEG
```

This informs MASM which segment names correspond to these registers. It does
not execute at run time.

The actual initialization is:

```asm
MOV AX, DATASEG
MOV DS, AX
MOV ES, AX
```

`DS` is needed for ordinary data references and DOS message pointers.
`ES` is needed because the later string-comparison instruction uses `ES:DI`
for its second memory operand.

On 8085 you normally think of an address such as `3000H` directly. In 8086 real
mode a reference such as `DS:SI` combines a segment value and an offset:

```text
physical address = segment × 16 + offset
```

---

## 8. Why initialize ES to the same segment as DS?

The two compared arrays both live in `DATASEG`:

```text
INPUT_BUFFER → DATASEG
PASSWORD     → DATASEG
```

But `CMPSB` has fixed implicit addressing rules:

```text
first byte  → DS:SI
second byte → ES:DI
```

Thus loading only `DS` would be insufficient. `ES` must identify the segment
containing `PASSWORD` too.

This is a useful example of an instruction whose operands are partly implicit.
8085's `MOV A,M` also has an implicit pointer, `HL`; x86 string instructions
have a more specialized pair of pointers and segment registers.

---

## 9. `MAIN PROC FAR` and the entry point

```asm
MAIN PROC FAR
```

declares the procedure's far call type. A far call can involve a code-segment
change, whereas a near call stays within the current code segment.

The final directive is:

```asm
END MAIN
```

It identifies the executable's entry point. Execution does not reach `MAIN`
because some source instruction called it.

The program exits through DOS rather than using a far `RET`, so the `FAR`
declaration should not be mistaken for a requirement to return to a caller here.

---

## 10. Display the title and prompt

```asm
LEA DX, TITLE_MSG
CALL PRINT_STRING
```

`LEA` loads the string's offset, not its first character. The pointer passed to
DOS is therefore `DS:DX`.

The same pattern displays the prompt at `TRY_AGAIN`:

```asm
LEA DX, PROMPT_MSG
CALL PRINT_STRING
CALL READ_PASSWORD
CALL CHECK_PASSWORD
```

The order matters. First collect a new entry; then compare that new entry.

In 8085 terms, loading a string pointer before calling an output routine is
similar to using `LXI H,message` before calling a monitor's print routine. The
exact monitor service depends on the 8085 environment; it is not an 8085 CPU
instruction equivalent to DOS.

---

## 11. `READ_PASSWORD` saves its working registers

```asm
READ_PASSWORD PROC NEAR
    PUSH AX
    PUSH BX
    XOR BX, BX
```

This procedure preserves `AX` and `BX` for its caller. Its result is written to
memory rather than returned in either register.

`BX` is the number of currently accepted characters. It also indexes the next
free buffer byte.

```text
BX = 0 → next accepted character goes into INPUT_BUFFER[0]
BX = 1 → next accepted character goes into INPUT_BUFFER[1]
```

`XOR BX,BX` sets both `BH` and `BL` to zero. Clearing just `BL` would leave an
unknown high byte in the array index.

---

## 12. Read one key through BIOS

```asm
READ_KEY:
    MOV AH, 00H
    INT 16H
```

BIOS keyboard service `00H` waits for a key and returns a character code in
`AL` with a scan code in `AH`.

Unlike DOS echoed line input, this service does not display each returned
character for this program. The routine also never prints the character or a
masking `*`.

Therefore “hidden” means there is no visible character feedback at all.

`INT 16H` is a software interrupt selecting a BIOS service. It is not equivalent
to an 8085 hardware keyboard interrupt. In 8085 systems, keyboard handling
depends on the board, I/O interface, and any monitor routines provided.

---

## 13. Enter completes the entry

```asm
CMP AL, 0DH
JE INPUT_FINISHED
```

`0DH` is carriage return, the Enter character used here.

`CMP` sets flags as if it had subtracted `0DH` from `AL`, but does not store the
subtraction result. `JE` jumps when the comparison was equal (`ZF=1`).

Your 8085 connection is:

```text
8086 CMP / JE → compare, then jump if zero/equal
8085 CPI / JZ → compare accumulator with immediate, then jump if zero
```

An empty entry also reaches this path. Its length is zero, so comparison fails.

---

## 14. Backspace changes the active length

```asm
CMP AL, 08H
JE HANDLE_BACKSPACE
```

At the handler:

```asm
CMP BX, 0
JE READ_KEY
DEC BX
JMP READ_KEY
```

If the buffer is empty, Backspace is ignored. Otherwise it subtracts one from
the active count.

It does not need to clear the removed byte. A later character overwrites that
position, or the final comparison ignores it because it lies beyond the count.

Example:

```text
keys: a d x Backspace m

after a:         count 1, active text "a"
after d:         count 2, active text "ad"
after x:         count 3, active text "adx"
after Backspace: count 2, active text "ad"
after m:         count 3, active text "adm"
```

---

## 15. Accept only printable ASCII

```asm
CMP AL, 20H
JB READ_KEY
CMP AL, 7EH
JA READ_KEY
```

The accepted interval is `20H..7EH`, including space and `~`.

`JB` and `JA` are unsigned comparisons. Character codes are being treated as
unsigned byte values here.

Most control or noncharacter key results fall outside this range and are
ignored. There is no special arrow-key operation in this program.

The rule also means leading and trailing spaces are literal password
characters. They are not automatically trimmed.

---

## 16. Check the limit before storing

```asm
CMP BX, MAX_INPUT
JAE READ_KEY
MOV INPUT_BUFFER[BX], AL
INC BX
JMP READ_KEY
```

Only indices 0 through 19 can receive a character. When the count is 20, extra
printable characters are discarded.

Because Enter and Backspace are handled earlier, both still work when the
buffer is full.

This is a saturating input count, not a circular buffer: character 21 does not
wrap around and overwrite character 1.

On 8085, indexed access would usually require calculating the buffer address
in a register pair first. MASM's `INPUT_BUFFER[BX]` expresses the base-plus-index
address directly.

---

## 17. Finish the read and save the count

```asm
INPUT_FINISHED:
    MOV INPUT_LEN, BL
    POP BX
    POP AX
    RET
```

`BX` is at most 20, so its low byte holds the whole count.

The `POP` order reverses the `PUSH` order. Otherwise the caller would receive
the saved registers in the wrong places.

There is no appended terminator. The checker must use `INPUT_LEN`.

On every retry, `XOR BX,BX` starts the active length at zero even though bytes
from a previous attempt may remain in the array.

---

## 18. `CHECK_PASSWORD` returns a Boolean in AL

```asm
PUSH CX
PUSH SI
PUSH DI
XOR CX, CX
MOV CL, INPUT_LEN
```

The routine preserves the caller's count and pointers, but intentionally leaves
its result in `AL`:

```text
AL = 1 → exact match
AL = 0 → mismatch
```

`XOR CX,CX` before loading `CL` prevents a stale `CH` from making the count
larger than the entered length.

---

## 19. Reject unequal lengths first

```asm
CMP CX, PASSWORD_LEN
JNE PASSWORD_WRONG
```

Only eight-character input proceeds to the byte comparison.

```text
"admin12"  → length 7 → reject
"admin123" → length 8 → compare bytes
"admin123x"→ length 9 → reject
```

This stops a correct prefix with extra characters from passing. It also ensures
that `REPE CMPSB` will execute with an initial count of 8 rather than 0.

That nonzero count is important because the zero flag after a zero-iteration
repeat would not be evidence that any password bytes were compared.

---

## 20. Set the two pointers

```asm
LEA SI, INPUT_BUFFER
LEA DI, PASSWORD
CLD
```

`CLD` clears the direction flag (`DF=0`). The string instruction will advance
both offsets after each byte.

```text
DF = 0 → SI and DI increase
DF = 1 → SI and DI decrease
```

Do not confuse direction flag with carry flag. `CLD` does not mean “clear the
carry”; that is `CLC`.

8085 has no direction flag or equivalent repeated string instruction. You
normally advance `HL` and another pointer explicitly.

---

## 21. What exactly does `REPE CMPSB` do?

```asm
REPE CMPSB
JNE PASSWORD_WRONG
```

`CMPSB` compares a byte at `DS:SI` with a byte at `ES:DI`. It sets flags, updates
the pointers according to `DF`, and does not change either memory byte.

With `REPE`, the CPU repeats while there are remaining bytes and each comparison
continues to be equal.

For this call, its effect is:

```text
while CX != 0:
    compare input[SI] with expected[DI]
    SI += 1
    DI += 1
    CX -= 1
    if compared bytes differed:
        stop
```

At the end, `JNE` examines the last comparison's zero flag.

```text
all eight matched → ZF=1 → do not jump to PASSWORD_WRONG
some byte differed→ ZF=0 → jump to PASSWORD_WRONG
```

## 22. Worked comparison: one wrong final character

Suppose input is `admin124`.

| Compared position | Entered | Expected | Remaining CX | Result |
| --- | --- | --- | --- | --- |
| 0 | `a` | `a` | 7 | equal |
| 1 | `d` | `d` | 6 | equal |
| 2 | `m` | `m` | 5 | equal |
| 3 | `i` | `i` | 4 | equal |
| 4 | `n` | `n` | 3 | equal |
| 5 | `1` | `1` | 2 | equal |
| 6 | `2` | `2` | 1 | equal |
| 7 | `4` | `3` | 0 | different |

Although `CX` reached zero, the final comparison was unequal. The routine
correctly rejects the entry by testing `ZF`, rather than accepting merely
because the counter became zero.

## 23. Return the result without undoing it

```asm
MOV AL, 1
JMP CHECK_DONE

PASSWORD_WRONG:
MOV AL, 0
```

Then:

```asm
POP DI
POP SI
POP CX
RET
```

`AX` is not restored because that would replace the Boolean result in `AL`.

The caller uses:

```asm
CMP AL, 1
JE ACCESS_GRANTED
```

This procedure communicates status as a register value. It does not define
carry as its success/failure interface.

---

## 24. Three attempts means three total entries

```asm
DEC ATTEMPTS
CMP ATTEMPTS, 0
JE SYSTEM_LOCKED
```

Starting at 3:

| Outcome | Before decrement | After decrement | Next action |
| --- | --- | --- | --- |
| First wrong entry | 3 | 2 | show 2; retry |
| Second wrong entry | 2 | 1 | show 1; retry |
| Third wrong entry | 1 | 0 | lock message; exit |

A correct entry jumps away before the decrement, so success does not consume
another attempt.

The question's word “retries” could suggest an initial entry plus three more.
The implementation is unambiguous: **three total entries**, not four.

---

## 25. Print the remaining count as one ASCII digit

```asm
MOV DL, ATTEMPTS
ADD DL, '0'
MOV AH, 02H
INT 21H
```

The count is only 2 or 1 on this path.

```text
2 + ASCII '0' = ASCII '2'
1 + ASCII '0' = ASCII '1'
```

This simple conversion would not print an arbitrary multi-digit integer. It
works because the possible values are known to be single digits.

The program does not display “Attempts left: 0”; zero branches to lockout
before this code.

---

## 26. Success, lockout, and process exit

`ACCESS_GRANTED` prints the success text and jumps past the lockout branch.
`SYSTEM_LOCKED` prints its message and falls through to the same exit label.

```asm
MOV AX, 4C00H
INT 21H
```

Here `AH=4CH` selects DOS termination and `AL=00H` is the process return status.

Both outcomes return status 0. A calling script cannot distinguish success
from lockout by the exit code alone.

Lockout state is not stored persistently. Restarting the process initializes
`ATTEMPTS` to 3 again.

---

## 27. `PRINT_STRING` protects AX

```asm
PRINT_STRING PROC NEAR
    PUSH AX
    MOV AH, 09H
    INT 21H
    POP AX
    RET
PRINT_STRING ENDP
```

The address is already in `DS:DX` when the caller invokes this helper.

Saving `AX` prevents the output service selection and result from destroying
the caller's `AX`. The helper does not append a newline automatically; messages
must contain `13,10` themselves when a newline is wanted.

## 28. Register roles at a glance

| Register | Role in this source |
| --- | --- |
| `AX` | Segment initialization, BIOS/DOS service selection |
| `AL` | Returned key; later checker Boolean |
| `AH` | Interrupt function; keyboard scan code on input return |
| `BX` | Active input length and buffer index in `READ_PASSWORD` |
| `CX` | Number of password bytes to compare |
| `SI` | Entered-password pointer |
| `DI` | Expected-password pointer |
| `DX` | Message offset; `DL` also prints the attempt digit |
| `DS`, `ES` | Segments required by the two comparison operands |

Registers are reused between procedures. These roles describe this program,
not permanent CPU rules for every instruction.

## 29. High-level pseudocode

```text
attempts = 3

repeat:
    print prompt
    length = 0

    repeat:
        key = bios_read_key_without_echo()
        if key == Enter:
            break
        if key == Backspace:
            if length > 0:
                length -= 1
        else if printable_ascii(key) and length < 20:
            input[length] = key
            length += 1

    matches = (length == 8)
    if matches:
        for i from 0 through 7:
            if input[i] != password[i]:
                matches = false
                break

    if matches:
        print "Access granted."
        terminate with status 0

    attempts -= 1
    if attempts == 0:
        print "SYSTEM LOCKED."
        terminate with status 0

    print "Incorrect password. Attempts left: ", attempts
```

This is an explanation of the assembly's behavior, not replacement source.

## 30. Edge cases you can reason through

| Entered keys | Active input on Enter | Result |
| --- | --- | --- |
| `admin123` | `admin123`, length 8 | accepted |
| `Admin123` | `Admin123`, length 8 | rejected: case differs |
| Enter alone | empty, length 0 | rejected |
| `admin123` then space | length 9 | rejected |
| `admin12x`, Backspace, `3` | `admin123`, length 8 | accepted |
| Backspace at empty buffer | still length 0 | safe; no underflow |
| More than 20 printable keys | first 20 active characters | extras ignored |

These are source-derived examples. They are not claims that a new interactive
DOSBox run was performed while writing this guide.

## 31. Important limits of the demonstration

The password is stored literally in the executable's data. Invisible typing
does not encrypt that stored value.

Comparison is case-sensitive and stops at the first different byte. There is
no hashing or constant-time comparison algorithm here.

Removed characters and previous attempts are not erased from the buffer; only
the active length determines what gets compared.

The attempt limit lasts for one process execution. “SYSTEM LOCKED” is a message
and termination path, not a machine-wide or persistent lock.

These facts matter when explaining what the assignment demonstrates: input
handling and control flow, rather than production authentication.

## 32. The 8085 ideas that transfer

| Familiar 8085 idea | Corresponding idea here |
| --- | --- |
| `CPI` and `JZ/JNZ` | `CMP` and `JE/JNE` |
| `INR` / `DCR` | `INC` / `DEC` |
| `LXI H,address` | Loading an offset into a pointer register |
| `MOV M,A` with HL | `MOV INPUT_BUFFER[BX],AL` with indexed addressing |
| Explicit loop over two strings | `CLD` and `REPE CMPSB` |
| `CALL`, `RET`, saved register pairs | Near calls and word `PUSH`/`POP` |
| Board/monitor input service | BIOS keyboard service in this DOS PC environment |

These are conceptual connections, not mechanically interchangeable instruction
spellings. In particular, 8085 has neither x86 segment registers nor `CMPSB`.

## 33. Exam-ready explanation

The program initializes the data and extra segments, then accepts up to twenty
printable password characters using BIOS keyboard interrupt `16H` without
echo. Backspace reduces the active length and Enter completes the entry.

It first compares the entered length against the eight-byte hardcoded password
length. If the lengths match, it uses `CLD` and `REPE CMPSB` to compare the bytes
at `DS:SI` and `ES:DI`. The checker returns 1 in `AL` for an exact match.

Success prints the access message. Failure decrements a counter initialized
to three; the first two failures allow another entry and the third terminates
with a lockout message. DOS interrupt `21H` handles output and process exit.
