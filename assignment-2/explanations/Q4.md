# Question 4 — sorting a user-sized array with Bubble Sort

Source: [Q4.ASM](../Q4.ASM).

This guide follows the program in the repository. It assumes that you know
8085 programming and are learning how the same ideas appear in 8086 MASM.

The task is:

```text
Read n → read n numbers → sort the numbers in ascending order → print them
```

The program accepts `n` from **1 through 20**. Each element is an unsigned
decimal number from **0 through 999**. Invalid input retries the current field.

The sorting algorithm is separate from the keyboard and display routines.
Understand the array traversal and Bubble Sort first; then connect the helpers.

---

## 1. What does ascending order mean?

Ascending order means that every element is less than or equal to the next:

```text
a[0] <= a[1] <= a[2] <= ... <= a[n-1]
```

For example:

```text
Before:  42   7   999   0   7
After:    0   7     7  42 999
```

Duplicates are allowed. Sorting does not remove either occurrence of `7`.

## 2. What Bubble Sort does

Bubble Sort compares adjacent elements. If the left element is larger,
it exchanges the two values.

```text
... 42 7 ... → ... 7 42 ...
```

One left-to-right pass moves the largest remaining value to the end of
the unsorted region. The following pass excludes that final value.

This program therefore uses **nested loops**: an outer loop for passes
and an inner loop for adjacent comparisons.

## 3. Program structure

The source declares:

```asm
STACKSEG SEGMENT PARA STACK 'STACK'
    DW 128 DUP (?)
STACKSEG ENDS
```

It also declares `DATASEG` for variables and `CODESEG` for instructions.

`DW 128 DUP (?)` reserves 128 uninitialized words, or 256 bytes, for the
CPU stack. Procedure return addresses, saved registers, and decimal digits
temporarily pushed by `PRINT_NUMBER` use that stack.

The array itself is stored in `DATASEG`, not on the CPU stack.

## 4. Directives versus executed instructions

`SEGMENT`, `ENDS`, `PROC`, `ENDP`, `DB`, `DW`, and `END` are assembler
directives. They describe the program or allocate storage.

`MOV`, `ADD`, `CMP`, `CALL`, and `JMP` are CPU instructions.

For example:

```asm
ASSUME CS:CODESEG, DS:DATASEG, SS:STACKSEG
```

tells MASM how the segment registers are intended to be used. It does
**not** initialize `DS` when the executable starts.

## 5. Initializing the data segment

The first instructions in `MAIN` are:

```asm
MOV AX, DATASEG
MOV DS, AX
```

Afterward, ordinary references to `ARRAY`, `ARRAY_LENGTH`, and the messages
use the intended data segment.

In an 8085 program you usually work in one flat 16-bit address space.
Here an address such as `DS:SI` combines a segment with an offset.

Do not interpret `SI = 2` as physical memory address `00002H`.

## 6. The messages

The source defines messages using `DB`, such as:

```asm
SIZE_MSG    DB 'Enter number of elements (1-20): $'
ELEMENT_MSG DB 'Enter element (0-999): $'
SPACE_MSG   DB ' $'
NEWLINE     DB 13,10,'$'
```

DOS function `INT 21H`, `AH = 09H` prints from `DS:DX` until `$`.
The terminator is not displayed.

`13,10` are carriage return and line feed: the conventional DOS newline.

## 7. The array length is one byte

```asm
ARRAY_LENGTH DB 0
```

The maximum length is 20, so one byte is sufficient.

When the program later copies this value into a 16-bit counter, it must
clear the high byte of that counter first.

This is the same general concern as constructing a register pair in 8085:
both halves must contain the intended value.

## 8. The elements are words

```asm
ARRAY DW 20 DUP (0)
```

Each value may reach 999, which does not fit in an unsigned byte:

```text
Largest byte = 255
999 decimal  = 03E7H
```

Each element therefore occupies a 16-bit word, or two bytes.
The complete array reserves 40 bytes.

## 9. Array indices are byte offsets

The source uses:

```asm
MOV ARRAY[SI], AX
ADD SI, 2
```

`SI` holds a **byte offset relative to ARRAY**:

| Element | SI | Bytes occupied relative to ARRAY |
| --- | ---: | --- |
| First | 0 | 0 and 1 |
| Second | 2 | 2 and 3 |
| Third | 4 | 4 and 5 |
| Twentieth | 38 | 38 and 39 |

`ARRAY[SI]` means memory at `DS:(offset ARRAY + SI)`.
MASM does not multiply `SI` by two automatically because `ARRAY` uses `DW`.

## 10. Little-endian storage

If an element is 999, its word value is `03E7H`.
8086 stores the low byte first:

```text
ARRAY + 0: E7H
ARRAY + 1: 03H
```

`MOV AX, ARRAY[SI]` loads both bytes as one word.
Your 8085 experience with a low byte and high byte in consecutive memory
locations is directly useful here.

## 11. The input buffer

```asm
INPUT_BUFFER DB 4,0,4 DUP (0)
```

For DOS buffered keyboard input, its layout is:

```text
+0  buffer capacity, including room for final carriage return
+1  number of typed characters returned, excluding carriage return
+2  first typed character
+3  second typed character, if present
+4  third typed character, if present
+5  carriage return after three characters
```

Capacity four allows at most three stored input characters before the CR.
The buffer holds text, not an already converted binary number.

For `123`, the character bytes are `'1'`, `'2'`, and `'3'`.

## 12. Main control flow

```text
MAIN
  initialize DS
  print title
READ_SIZE
  read and validate n
  retry bad n
READ_ELEMENTS
  read n valid elements
  retry a bad element in its current slot
SORT_ARRAY
  call BUBBLE_SORT
PRINT_ARRAY
  print n elements
PRINT_COMPLETE
  print newline and exit
```

The labels are branch destinations inside `MAIN`. They do not themselves
create new procedures or save a return address.

## 13. Calling PRINT_STRING

```asm
LEA DX, TITLE_MSG
CALL PRINT_STRING
```

`LEA` loads the message's offset, not its first character.
`CALL` saves the return address on `SS:SP` and transfers control.

The helper uses `DS:DX`, prints the `$`-terminated string, and returns
using `RET`.

In 8085 terms, passing a pointer is like loading a register pair with
the address of a string before calling a printing subroutine.

## 14. Reading the count

The important part of `READ_SIZE` is:

```asm
CALL READ_NUMBER
JC BAD_SIZE

CMP AX, 1
JB BAD_SIZE
CMP AX, 20
JA BAD_SIZE

MOV ARRAY_LENGTH, AL
JMP READ_ELEMENTS
```

`READ_NUMBER` returns the converted value in `AX`.
It reports a parsing failure by setting the Carry Flag.

The caller then performs the separate **range check** for `n`.

## 15. Parsing validity and range validity are different

`0` consists of valid decimal digits, so `READ_NUMBER` succeeds.
However, it is an invalid array length because `n` must be at least one.

Similarly, `21` parses correctly but exceeds the permitted length.

```text
"0"   → parse succeeds → range check fails
"21"  → parse succeeds → range check fails
"2x"  → parse fails
""    → parse fails
"20"  → parse succeeds → range check succeeds
```

Keeping these two checks separate makes the parser reusable for array values.

## 16. What JB and JA mean

After `CMP AX, 1`, `JB` means unsigned **below**.
After `CMP AX, 20`, `JA` means unsigned **above**.

`CMP` updates flags as if subtracting the second operand from the first,
but it does not store the subtraction result.

For unsigned comparisons:

```text
JB:  CF = 1
JA:  CF = 0 and ZF = 0
JBE: CF = 1 or ZF = 1
```

8085 also uses flags after `CMP`; its instruction names and available
combinations differ. These x86 branches must not be treated as signed tests.

## 17. Retrying a bad size

```asm
BAD_SIZE:
    LEA DX, INVALID_MSG
    CALL PRINT_STRING
    JMP READ_SIZE
```

The program prints an error and asks for the count again.
It does not exit and does not start reading elements.

The `JMP` is unconditional: it does not inspect the flags.

## 18. Preparing the element input loop

```asm
XOR SI, SI
XOR CX, CX
MOV CL, ARRAY_LENGTH
```

This establishes:

```text
SI = 0             first element's byte offset
CX = ARRAY_LENGTH  number of successful entries still needed
```

Clearing `CX` before writing `CL` guarantees `CH = 0`.
Otherwise, stale bits in `CH` could create a much larger loop count.

## 19. Reading and storing one element

```asm
CALL READ_NUMBER
JC BAD_ELEMENT

CMP AX, 999
JA BAD_ELEMENT

MOV ARRAY[SI], AX
ADD SI, 2
LOOP READ_ONE_ELEMENT
```

A successful parse gives an unsigned number in `AX`.
The element range check enforces the advertised upper limit.

The current three-character input limit already bounds a valid decimal
conversion to 999, so that check is redundant under this buffer configuration.
It still documents the field's intended range.

## 20. Why an invalid element does not consume a slot

`BAD_ELEMENT` jumps back to `READ_ONE_ELEMENT` before the store,
the pointer increment, and the `LOOP` instruction.

For example:

```text
SI = 4, CX = 3
typed "x" → retry with SI = 4, CX = 3
typed "42" → store third element, SI = 6, CX = 2
```

`READ_NUMBER` preserves `SI` and `CX` while using its own pointer and counter.
Without that preservation, the surrounding input loop would be corrupted.

## 21. LOOP is not a test before the first iteration

```asm
LOOP READ_ONE_ELEMENT
```

decrements `CX`, then branches if the result is nonzero.
It does not change arithmetic flags.

Conceptually:

```text
CX = (CX - 1) modulo 65536
if CX != 0: jump
```

If a loop body starts with `CX = 0`, reaching `LOOP` wraps it to `FFFFH`.
Here the validated length is at least one, so the input loop is safe.

An 8085 counter loop often uses `DCR` followed by `JNZ`; its flag behavior
is different from x86 `LOOP` even though the counting idea is similar.

## 22. Entering BUBBLE_SORT

```asm
CALL BUBBLE_SORT
```

The procedure accesses the global `ARRAY` and `ARRAY_LENGTH` directly.
No argument is passed in `AX` or on the CPU stack.

It saves `AX`, `BX`, `CX`, `DX`, and `SI` before changing them.
The sorted array is the result; restoring the registers does not undo memory writes.

## 23. The zero-or-one-element guard

```asm
CMP ARRAY_LENGTH, 1
JBE SORT_DONE
```

An empty or single-element array needs no comparison.
The normal input path permits only the single-element case.

The empty-array guard also makes the sorting procedure safe for a hypothetical
caller supplying length zero. It prevents decrementing zero into a huge count.

The procedure still assumes its length does not exceed the allocated capacity.

## 24. DX holds the pass comparison count

```asm
XOR DX, DX
MOV DL, ARRAY_LENGTH
DEC DX
```

For `n = 5`, `DX` becomes four.

```text
Pass 1: 4 comparisons
Pass 2: 3 comparisons
Pass 3: 2 comparisons
Pass 4: 1 comparison
```

The count is a number of adjacent comparisons, not a byte offset.

## 25. Restarting each pass

```asm
OUTER_LOOP:
    XOR SI, SI
    MOV CX, DX
```

Every pass starts again at the first array word.
`CX` receives the current pass's remaining comparison count.

`DX` survives the inner loop so it can be reduced once the pass is complete.

The counters have different roles:

```text
DX: comparisons allotted to this pass
CX: comparisons still to execute in this pass
```

## 26. Loading an adjacent pair

```asm
MOV AX, ARRAY[SI]
MOV BX, ARRAY[SI+2]
```

For `SI = 0`, these are elements zero and one.
For `SI = 2`, these are elements one and two.

The pairs overlap by one element as the scan proceeds.
That overlap is how one large value can move repeatedly toward the right.

Both operands are loaded before either memory location is overwritten.

## 27. The comparison and no-swap path

```asm
CMP AX, BX
JBE NO_SWAP
```

If the left value is already less than or equal to the right value,
the pair is in the desired order.

```text
AX = 7, BX = 42 → no swap
AX = 7, BX = 7  → no swap
AX = 42, BX = 7 → swap
```

The comparison is unsigned, matching the accepted range `0..999`.

## 28. Exchanging the pair

```asm
MOV ARRAY[SI], BX
MOV ARRAY[SI+2], AX
```

Suppose the loaded registers contain:

```text
AX = 42
BX = 7
```

The first write stores 7 into the left position.
The second stores 42 into the right position.

The original values remain safe in the registers throughout the exchange.
No separate temporary array is required.

## 29. Moving to the next pair

```asm
NO_SWAP:
    ADD SI, 2
    LOOP INNER_LOOP
```

Both the swap and no-swap paths reach this label.
Every comparison therefore advances by exactly one word.

In 8085, moving to the next word often requires two `INX H` instructions.
Here `ADD SI, 2` performs that pointer movement directly.

## 30. Why the largest value reaches the end

Consider one pass through:

```text
5 1 4 2
```

```text
Compare 5,1 → 1 5 4 2
Compare 5,4 → 1 4 5 2
Compare 5,2 → 1 4 2 5
```

At every comparison, the larger of the pair becomes the right element.
Consequently, after the full pass, the largest value seen is at the end.

The array may still be unsorted to its left, which is why more passes follow.

## 31. Shrinking the unsorted region

```asm
DEC DX
JNZ OUTER_LOOP
```

Once a pass completes, its largest remaining value is in its final position.
The next pass needs one fewer comparison.

`DEC DX` sets the Zero Flag when the comparison count becomes zero.
`JNZ` uses that flag to decide whether another pass is required.

Unlike `LOOP`, this pair explicitly depends on the flags from `DEC`.

## 32. A complete worked sorting trace

For `n = 4` and values `5, 1, 4, 2`:

| Pass | DX at start | Comparisons | Array after pass |
| --- | ---: | --- | --- |
| 1 | 3 | `(5,1)`, `(5,4)`, `(5,2)` | `1 4 2 5` |
| 2 | 2 | `(1,4)`, `(4,2)` | `1 2 4 5` |
| 3 | 1 | `(1,2)` | `1 2 4 5` |

The final pass still executes even though the second pass produced sorted order.
The source has no flag recording whether a pass made any exchange.

## 33. Register trace for the first pass

```text
Before pass: DX=3, SI=0, CX=3

Pair 1: AX=5, BX=1, swap
        SI=2, CX becomes 2

Pair 2: AX=5, BX=4, swap
        SI=4, CX becomes 1

Pair 3: AX=5, BX=2, swap
        SI=6, CX becomes 0

End pass: DX becomes 2, restart SI at 0
```

Notice that `SI = 6` after the pass is a pointer position, not the value
of the largest array element.

## 34. Why equal values are not exchanged

`JBE` includes equality.
The algorithm exchanges only pairs whose left value is strictly larger.

Imagine equal numbers carrying invisible labels:

```text
7a 3 7b
```

Sorting gives `3 7a 7b`; equal elements do not cross each other.
This property is called **stability**.

The numeric output alone cannot display those labels, but the branch rule
establishes the property.

## 35. Comparison count and storage

For `n` elements, the exact number of comparisons is:

```text
(n-1) + (n-2) + ... + 1 = n(n-1)/2
```

At the maximum length of 20, this is 190 comparisons.
For one element, it is zero.

The sorting time is `O(n²)`, including already sorted input.
The sort uses `O(1)` additional working storage: a fixed number of registers
and saved register words, independent of `n`.

## 36. Returning from the sort

The procedure restores its registers in reverse order:

```asm
POP SI
POP DX
POP CX
POP BX
POP AX
RET
```

That is the Last In, First Out rule familiar from the 8085 stack.

The procedure does not promise to preserve flags.
Its caller obtains the sorted values from `ARRAY`, not from condition flags.

## 37. Preparing the output traversal

After printing `RESULT_MSG`, `MAIN` uses:

```asm
XOR SI, SI
XOR CX, CX
MOV CL, ARRAY_LENGTH
```

This is a fresh traversal of the first `n` words.
The old input-loop state is not reused.

The output loop calls `PRINT_NUMBER` with each word in `AX`.

## 38. Avoiding a trailing space

```asm
MOV AX, ARRAY[SI]
CALL PRINT_NUMBER

ADD SI, 2
DEC CX
JZ PRINT_COMPLETE

LEA DX, SPACE_MSG
CALL PRINT_STRING
JMP PRINT_ARRAY
```

After printing a number, the program consumes that element from the count.
If no elements remain, it exits before printing a space.

For `n = 1`, the single number is printed without a separator.

## 39. READ_NUMBER: register contract

The parser saves `BX`, `CX`, `DX`, and `SI`.
It returns:

```text
Success: AX = converted number, CF = 0
Failure: CF = 1; AX is not a usable result
```

The caller's array pointer and outer loop counter are therefore preserved.

`AX` is deliberately not restored because it carries the return value.

## 40. Reading a buffered line

```asm
MOV INPUT_BUFFER[1], 0
LEA DX, INPUT_BUFFER
MOV AH, 0AH
INT 21H
```

The program clears the previous length byte, then asks DOS to read and echo
a line into the buffer.

It next prints a line-feed character with DOS function `02H` so the next
message appears on the following row after the Enter action.

The buffer's returned count, rather than `$` or a zero byte, determines
how many typed characters the parser examines.

## 41. Rejecting an empty line

```asm
XOR CX, CX
MOV CL, INPUT_BUFFER[1]
CMP CX, 0
JE NUMBER_INVALID
```

No digits is different from the digit `0`.

```text
empty input: count = 0 → invalid
input "0":   count = 1 → valid decimal zero
```

The count check also prevents entering the digit loop with `CX = 0`.

## 42. Beginning the conversion

```asm
LEA SI, INPUT_BUFFER[2]
XOR AX, AX
```

`SI` now points at the first typed character, beyond the two-byte header.
`AX` is the numeric accumulator.

The conversion repeatedly applies:

```text
new value = old value × 10 + new digit
```

This is the same decimal positional notation you use by hand.

## 43. Validating and converting one digit

```asm
MOV DL, [SI]
CMP DL, '0'
JB NUMBER_INVALID
CMP DL, '9'
JA NUMBER_INVALID

SUB DL, '0'
XOR DH, DH
MOV BX, DX
```

ASCII digit codes are consecutive. Subtracting `'0'` turns `'7'` into 7.
Clearing `DH` makes the complete `DX` register hold that unsigned digit.

The digit is copied to `BX` before multiplication overwrites `DX`.

## 44. Why MUL DX overwrites DX

```asm
MOV DX, 10
MUL DX
ADD AX, BX
```

For a 16-bit operand, unsigned multiplication means:

```text
AX × operand → DX:AX
```

`DX:AX` is a 32-bit result, with `DX` as its high word.
The input value of `DX` is used as the multiplier before the result is stored.

Here the partial products are small, so the high result word is zero.
The saved digit in `BX` is then added to the low result word in `AX`.

8085 has no equivalent general multiplication instruction; you would build
the multiply-by-ten operation using additions, shifts, or a subroutine.

## 45. Conversion trace for 507

| Character | Digit saved in BX | AX before multiply | AX after ×10 + digit |
| --- | ---: | ---: | ---: |
| `'5'` | 5 | 0 | 5 |
| `'0'` | 0 | 5 | 50 |
| `'7'` | 7 | 50 | 507 |

The pointer advances with `INC SI` and the count decreases through `LOOP`.
After the third digit, the loop stops without examining the carriage return.

## 46. Returning parsing status

```asm
CLC
JMP READ_NUMBER_DONE

NUMBER_INVALID:
    STC
```

`CLC` explicitly clears the Carry Flag for success.
`STC` explicitly sets it for failure.

The following `POP` instructions and `RET` do not change `CF`, so the caller's
`JC BAD_SIZE` or `JC BAD_ELEMENT` observes the intended status.

This flag is a procedure result, not an arithmetic overflow report from `MUL`.

## 47. Accepted and rejected text

| Typed text stored in the buffer | Parsing outcome | Count field outcome |
| --- | --- | --- |
| `007` | Value 7 | Valid |
| `020` | Value 20 | Valid |
| `000` | Value 0 | Rejected as a count |
| `999` | Value 999 | Rejected as a count; valid element |
| `-1` | Invalid character | Retry |
| ` 7` | Invalid space | Retry |
| `7 ` | Invalid space | Retry |
| `1a` | Invalid character | Retry |

The parser does not trim whitespace or accept a leading plus sign.

## 48. Input length is enforced by the DOS buffer

There is no separate parser check for more than three digits.
The current DOS buffer limits the stored text to three characters.

Extra keystrokes at a full DOS line buffer are not a reliable way to supply
an invalid four-digit number to this parser: the excess characters are not
part of the returned three-character string under normal DOS line editing.

For example, attempting to type `1000` can leave the stored text as `100`.
Do not describe this as an explicit “reject numbers above 999” input path.

The arithmetic also relies on the short buffer: the parser has no general
16-bit overflow check for an arbitrarily enlarged decimal input buffer.

## 49. PRINT_NUMBER: preserving the caller

```asm
PUSH AX
PUSH BX
PUSH CX
PUSH DX
```

The helper saves the input value and the registers used for conversion.
In particular, preserving `CX` protects `MAIN`'s remaining-element count.

The helper prints an unsigned decimal representation.
It does not print a sign, separator, or newline.

## 50. The special zero case

```asm
CMP AX, 0
JNE DIVIDE_NUMBER

MOV DL, '0'
MOV AH, 02H
INT 21H
JMP PRINT_NUMBER_DONE
```

Zero is printed directly as the character `'0'`.
The routine then skips the digit-division and digit-pop loops.

This matters because no temporary digit words have been pushed on that path.

## 51. Dividing a number into decimal digits

For a nonzero value:

```asm
XOR CX, CX
MOV BX, 10
```

Then each iteration performs:

```asm
XOR DX, DX
DIV BX
PUSH DX
INC CX
CMP AX, 0
JNE DIVIDE_LOOP
```

Word `DIV` divides `DX:AX` by `BX`:

```text
AX = quotient
DX = remainder
```

## 52. Why clear DX before every DIV?

The dividend is the complete `DX:AX` pair, not just `AX`.

Setting `DX = 0` makes the dividend equal to the current unsigned word in `AX`.
On the next iteration, `DX` contains the previous remainder, so it must be
cleared again.

Failing to do this would divide a different, larger number and can cause
a quotient-overflow exception.

## 53. A print conversion trace

For `AX = 507`:

```text
507 / 10 → quotient 50, remainder 7 → PUSH 7
 50 / 10 → quotient  5, remainder 0 → PUSH 0
  5 / 10 → quotient  0, remainder 5 → PUSH 5
```

Digits are discovered from right to left.
The CPU stack reverses their order:

```text
POP 5 → print '5'
POP 0 → print '0'
POP 7 → print '7'
```

That is why the output is `507` instead of `705`.

## 54. Printing one remainder digit

```asm
POP DX
ADD DL, '0'
MOV AH, 02H
INT 21H
LOOP PRINT_DIGIT
```

A remainder is a binary value from zero through nine.
Adding the ASCII code for `'0'` turns it into a printable digit.

The digit count in `CX` ensures exactly as many words are popped as were
pushed by the division loop.

## 55. Two uses of the CPU stack

Within `PRINT_NUMBER`, the stack temporarily contains both saved registers
and generated digits:

```text
most recently pushed digit    ← current top during conversion
earlier digit words
saved DX
saved CX
saved BX
saved AX
return address
```

All digit words must be removed before restoring the saved registers.
Otherwise a digit would be mistaken for a saved register or return address.

## 56. PRINT_STRING preserves the output loop

The helper saves and restores `AX`, `CX`, and `DX` around DOS function `09H`.

Its explicit preservation is useful because the output loop calls it to
print a space between elements.

The pointer is passed in `DS:DX` and must refer to a `$`-terminated message.
This helper is not used to print the numeric array's raw memory.

## 57. Ending the program

```asm
MOV AX, 4C00H
INT 21H
```

This sets DOS function `4CH` in `AH` and success status zero in `AL`.

The program reaches this point after printing the sorted array and a newline.
Bad user input retries its field instead of taking a separate error exit.

`END MAIN` identifies the executable's entry point for the assembler/linker;
it is not the instruction that terminates execution.

## 58. Whole-program pseudocode

```c
do {
    result = read_decimal_up_to_three_stored_digits();
} while (!result.valid || result.value < 1 || result.value > 20);

n = result.value;

for (i = 0; i < n; ) {
    result = read_decimal_up_to_three_stored_digits();
    if (!result.valid || result.value > 999)
        continue;                  // retry the same element
    array[i] = result.value;
    i++;
}

for (comparisons = n - 1; comparisons > 0; comparisons--) {
    for (i = 0; i < comparisons; i++) {
        if (array[i] > array[i + 1])
            swap(array[i], array[i + 1]);
    }
}

for (i = 0; i < n; i++) {
    print_unsigned_decimal(array[i]);
    if (i + 1 < n)
        print(" ");
}
print_newline();
```

The C array index `i` corresponds to the assembly byte offset `SI = 2*i`.

## 59. Boundary cases to explain

| Input situation | Actual behavior |
| --- | --- |
| `n = 1` | Reads and prints one value; skips sorting comparisons |
| `n = 20` | Uses all 40 array bytes; performs 190 comparisons |
| Values already sorted | Still performs every scheduled comparison |
| Values reverse sorted | Repeated adjacent swaps produce ascending order |
| Equal values | Preserved; equal pairs are not swapped |
| Element `0` | Accepted and printed using the zero special case |
| Element `999` | Fits in a word and prints as three digits |
| Empty field | Parser fails and the same field is retried |
| Negative text | Rejected because `'-'` is not a decimal digit |

## 60. Connecting the program to 8085

| Idea | Familiar 8085 approach | This 8086 program |
| --- | --- | --- |
| Memory pointer | `HL`, sometimes `DE` | `SI` plus the `ARRAY` label |
| Move to next byte | `INX H` | `INC SI` where needed |
| Move to next word | Two byte increments | `ADD SI, 2` |
| Compare numbers | `CMP` and conditional jumps | Word `CMP`, unsigned `JBE` |
| Count repetitions | Decrement and conditional jump | `LOOP` or `DEC`/`JNZ` |
| Save temporary state | `PUSH`/`POP` register pairs | `PUSH`/`POP` 16-bit registers |
| Decimal multiplication | Software routine | Word `MUL` |
| Decimal division | Software routine | Word `DIV` |
| Console I/O | Depends on monitor/system | DOS `INT 21H` services |

These are conceptual correspondences, not instructions that can be substituted
one for one. In particular, 8085 has no x86 segment registers or DOS services.

## 61. What to remember for an exam

Explain the program in this order:

1. Validate the number of elements and read that many unsigned word values.
2. Compare adjacent words from left to right.
3. Swap only if the left word is larger than the right word.
4. Each pass places the largest remaining word at the unsorted region's end.
5. Reduce the comparison count by one and repeat.
6. Print all words in decimal, with spaces only between them.

The central assembly sequence is:

```asm
MOV AX, ARRAY[SI]
MOV BX, ARRAY[SI+2]
CMP AX, BX
JBE NO_SWAP
MOV ARRAY[SI], BX
MOV ARRAY[SI+2], AX
```

If you can trace that sequence and explain why `SI` advances by two,
you understand the sorting core of this program.
