# Question 5 — balanced and properly nested brackets

Source: [Q5.ASM](../Q5.ASM).

This guide explains the actual MASM implementation using ideas familiar from
8085 programming: memory arrays, pointers, counters, comparisons, and branches.

The program reads one line containing the bracket characters:

```text
( ) { } [ ]
```

It prints **Balanced** only when every closing bracket matches the most recent
unmatched opening bracket and no opening brackets remain at the end.

It uses an array in the data segment as a **software stack**.
This is separate from the CPU stack used for `CALL`, `PUSH`, and `POP`.

---

## 1. Balanced means more than equal counts

These inputs are balanced:

```text
()
[]{}
([])
{[()]}
```

These inputs are not:

```text
(
)
([)]
{]
```

`([)]` has equal numbers of opening and closing brackets, but its nesting
crosses. The `')'` tries to close `'('` while `'['` is still open inside it.

Counting brackets alone cannot detect that error.

## 2. The Last In, First Out rule

For:

```text
{ [ ( ) ] }
```

the opening brackets arrive in this order:

```text
{ then [ then (
```

They must close in the reverse order:

```text
) then ] then }
```

This is exactly the Last In, First Out rule, abbreviated **LIFO**.
It is why a stack is the natural data structure for this question.

## 3. The algorithm before the assembly

```text
Start with an empty stack.

For each input character:
    If it is an opening bracket:
        push it.
    If it is a closing bracket:
        reject if the stack is empty;
        pop the latest opener;
        reject if its type does not match.
    Otherwise:
        reject the input.

After the scan:
    accept only if the stack is empty.
```

This source accepts **brackets only**. It does not ignore ordinary expression
characters, digits, spaces, or tabs.

## 4. Simplified MASM segment directives

The source begins with:

```asm
.MODEL SMALL
.STACK 100H
```

The small memory model provides one code segment and one data group within
the model's size limits. `.STACK 100H` reserves 256 bytes for the CPU stack.

The subsequent `.DATA` and `.CODE` directives introduce data and instructions.
They provide a shorter form than the explicitly named segments in other
assignment programs.

These are assembler/linker declarations, not instructions executed by 8086.

## 5. The constant MAX_INPUT

```asm
MAX_INPUT EQU 80
```

`EQU` defines an assembly-time constant.
Every reference to `MAX_INPUT` uses the value 80.

It does not allocate a variable containing 80 and cannot be changed by the
running program.

Compare:

```asm
TOP_INDEX DB 0
```

which does allocate one byte of memory that the running program updates.

## 6. Message strings

```asm
TITLE_TEXT    DB 13,10,'BRACKET BALANCE CHECKER',13,10,'$'
PROMPT_TEXT   DB 'Enter brackets using (), {}, and []: $'
BALANCED_TEXT DB 13,10,'Balanced',13,10,'$'
NOT_BAL_TEXT  DB 13,10,'Non-Balanced',13,10,'$'
```

`DB` defines the bytes, including ASCII character codes.
`13,10` are carriage return and line feed.

The final `$` is required by the DOS string-printing service used here.
It does not terminate the input scan.

## 7. The keyboard input buffer

```asm
INPUT_BUFFER DB MAX_INPUT+1, 0, (MAX_INPUT+1) DUP (0)
```

With `MAX_INPUT = 80`, this reserves:

```text
1 byte:  DOS capacity = 81, including room for carriage return
1 byte:  returned character count, initially zero
81 bytes: character area, including room for final carriage return
```

The complete buffer occupies 83 bytes.
Under normal DOS buffered input semantics it holds at most 80 typed characters
plus the final carriage return.

## 8. Input text is not zero-terminated here

The scanner does not search for a zero byte or `$`.
It reads exactly the character count returned by DOS.

For input `([])`, the relevant buffer layout is:

```text
INPUT_BUFFER + 0 = 81
INPUT_BUFFER + 1 = 4
INPUT_BUFFER + 2 = '('
INPUT_BUFFER + 3 = '['
INPUT_BUFFER + 4 = ']'
INPUT_BUFFER + 5 = ')'
INPUT_BUFFER + 6 = carriage return
```

The scanner examines offsets `+2` through `+5`, not the CR at `+6`.

## 9. The simulated bracket stack

```asm
BRACKET_STACK DB MAX_INPUT DUP (0)
TOP_INDEX     DB 0
```

The array reserves 80 byte-sized entries.
An opening bracket is one character, so each stack item needs only one byte.

`TOP_INDEX` is the current **number of items** and the **next free array index**.
Despite the name, it is not the occupied index of the current top item.

## 10. What TOP_INDEX means

| TOP_INDEX | Meaning | Top item's array index |
| ---: | --- | --- |
| 0 | Empty | None |
| 1 | One unmatched opener | 0 |
| 2 | Two unmatched openers | 1 |
| 80 | Full | 79 |

For a nonempty stack:

```text
top item = BRACKET_STACK[TOP_INDEX - 1]
```

This convention makes push and pop simple:

```text
push: write at count, then increment count
pop:  decrement count, then read at count
```

## 11. CPU stack versus bracket stack

There are two different stack mechanisms:

| Stack | Storage and pointer | Contents |
| --- | --- | --- |
| CPU stack | `SS:SP` | Return addresses and saved registers |
| Bracket stack | `DS:BRACKET_STACK`, `TOP_INDEX` | Unmatched opening characters |

The bracket-handling code does not execute `PUSH AL` or `POP AL`.
8086's ordinary `PUSH` and `POP` operate on words, while these bracket entries
are bytes stored using normal memory instructions.

## 12. The 8085 connection

You know `PUSH B`, `POP B`, `CALL`, and `RET` from 8085.
Those use the hardware stack addressed by `SP`.

The same LIFO concept can also be implemented manually in an ordinary array.
On 8085, you could keep a software stack base in a register pair and manage
a count separately.

This program does that in the 8086 data segment, leaving the CPU stack for
procedure calls and saved registers.

## 13. Program entry and DS initialization

```asm
MAIN PROC
    MOV AX, @DATA
    MOV DS, AX
```

`@DATA` names the data group associated with the simplified memory model.
Loading `DS` makes labels such as `INPUT_BUFFER` and `TOP_INDEX` address
the intended data.

`AX` is used as an intermediate because an immediate value cannot be moved
directly into `DS` with this form of `MOV`.

## 14. Printing the title and prompt

```asm
LEA DX, TITLE_TEXT
CALL PRINT_STRING

LEA DX, PROMPT_TEXT
CALL PRINT_STRING
```

`LEA DX, label` loads the label's offset.
The helper interprets `DS:DX` as a pointer to a `$`-terminated string.

`CALL` saves the next instruction's address on the CPU stack.
`RET` in the helper returns there.

## 15. Reading the line

```asm
LEA DX, INPUT_BUFFER
MOV AH, 0AH
INT 21H
```

This asks DOS to perform buffered line input.
DOS reads and echoes the characters and supplies the returned count.

`INT 21H` is an operating-system interface, not an inherent bracket-checking
feature of the 8086 processor.

8085 input routines depend on the monitor or hardware attached to that system;
there is no direct 8085 equivalent of this DOS call.

## 16. Preparing the scan

```asm
MOV TOP_INDEX, 0
LEA SI, INPUT_BUFFER[2]
XOR CX, CX
MOV CL, INPUT_BUFFER[1]
```

The state becomes:

```text
TOP_INDEX = 0           no unmatched opening brackets
SI = first input byte   skip the two-byte DOS header
CX = input length       number of characters still to inspect
```

Clearing all of `CX` before loading `CL` ensures `CH = 0`.

## 17. Why reset only TOP_INDEX?

The source does not clear all 80 stack entries before scanning.
It only resets the count.

That is sufficient: entries with indices at or above `TOP_INDEX` are logically
outside the stack and are never consulted as active items.

An old byte can remain in array storage after a pop without remaining part
of the logical stack.

This distinction between stored bytes and logical size appears in many
array-based data structures.

## 18. The empty-input guard

```asm
JCXZ CHECK_STACK_EMPTY
```

`JCXZ` branches if `CX` itself is zero.
It does not test the Zero Flag left by the preceding instruction.

Empty input goes directly to the final empty-stack check.
Because `TOP_INDEX` is zero, this implementation prints `Balanced`.

That is a deliberate consequence of the implemented logic: an empty sequence
contains no unmatched brackets.

## 19. Why not enter the loop with CX = 0?

The character loop ends with:

```asm
LOOP CHECK_NEXT_CHARACTER
```

`LOOP` decrements `CX`, then branches if the result is nonzero.
Starting the body with zero would still process a byte and would then wrap
the count to `FFFFH`.

The `JCXZ` guard prevents that invalid traversal.

This differs from an 8085 `DCR`/`JNZ` pair in flag behavior: x86 `LOOP`
does not update arithmetic flags.

## 20. Loading one character

```asm
CHECK_NEXT_CHARACTER:
    MOV AL, [SI]
```

`SI` is a byte pointer into the typed input.
`AL` receives that character's ASCII code.

The square brackets mean memory access. They do not indicate a bracket
character in the input language.

Compare the 8085 idea:

```asm
MOV A, M
```

where `HL` supplies the address. Here `DS:SI` supplies it.

## 21. Dispatching opening brackets

```asm
CMP AL, '('
JE PUSH_OPENING
CMP AL, '{'
JE PUSH_OPENING
CMP AL, '['
JE PUSH_OPENING
```

All three opening characters share the same handler.
That handler stores the actual character from `AL`.

`CMP` changes flags as though subtracting, but does not modify `AL`.
`JE` branches when the Zero Flag indicates equality.

Thus repeated comparisons can test the same input character safely.

## 22. Dispatching closing brackets

```asm
CMP AL, ')'
JE CHECK_ROUND
CMP AL, '}'
JE CHECK_CURLY
CMP AL, ']'
JE CHECK_SQUARE
```

Each closer selects the opening type it requires.
All three paths then use the same matching-and-pop code.

This avoids duplicating the underflow check and stack access for every type.

## 23. The invalid-character path

If none of the six comparisons matched:

```asm
JMP NON_BALANCED
```

The source immediately rejects the input.

```text
"()"    → allowed characters
"( )"   → rejected because of the space
"(a)"   → rejected because of 'a'
"2+3"   → rejected because of '2'
```

Do not describe this as a checker that ignores non-bracket text in an
arithmetic expression. That would require different character handling.

## 24. Loading TOP_INDEX into a word register

The push handler starts:

```asm
XOR BX, BX
MOV BL, TOP_INDEX
```

The stored index is a byte, but the memory addressing mode uses `BX`.
Clearing `BX` before writing `BL` zero-extends the count.

For example:

```text
TOP_INDEX = 3
BX = 0003H
```

Without clearing `BH`, an old high byte could produce an incorrect address.

## 25. Checking stack capacity

```asm
CMP BL, MAX_INPUT
JAE NON_BALANCED
```

`JAE` means unsigned above or equal.
If the count is already 80, no more items fit.

The valid indices are `0..79`, so the check happens **before** the write.
At count 79, one more push writes index 79 and increases the count to 80.

Under the normal 80-character input limit, overflow cannot occur solely from
valid input characters: no line contains more than 80 possible pushes.
The guard still protects the write if its assumptions change.

## 26. Pushing the opening character

```asm
MOV BRACKET_STACK[BX], AL
INC TOP_INDEX
JMP CHARACTER_DONE
```

Suppose the current stack is:

```text
BRACKET_STACK[0] = '('
TOP_INDEX = 1
```

Reading `'['` writes index 1, then sets the count to two:

```text
logical stack, bottom to top: ( [
TOP_INDEX = 2
```

The jump skips all closing-bracket handlers for this character.

## 27. Selecting the expected opener

The handlers are:

```asm
CHECK_ROUND:
    MOV DL, '('
    JMP CHECK_CLOSING

CHECK_CURLY:
    MOV DL, '{'
    JMP CHECK_CLOSING

CHECK_SQUARE:
    MOV DL, '['
```

`DL` now holds the opener required by the current closer:

| Input closer | Expected opener in DL |
| --- | --- |
| `)` | `(` |
| `}` | `{` |
| `]` | `[` |

## 28. Fall-through is part of the control flow

`CHECK_SQUARE` has no explicit jump after `MOV DL, '['`.
The next label in the source is `CHECK_CLOSING`, so execution continues there.

Labels do not stop execution. They only name instruction addresses.

The round and curly handlers need explicit jumps because their code is
positioned before other handlers that would otherwise overwrite `DL`.

This is the same fall-through principle used in 8085 assembly.

## 29. Detecting a closer with no opener

```asm
CHECK_CLOSING:
    CMP TOP_INDEX, 0
    JE NON_BALANCED
```

An empty stack means there is no unmatched opener available.
Examples include:

```text
)
][
())
```

The check occurs before decrementing the count.
Otherwise a byte count of zero would wrap to 255 and lead to an invalid access.

## 30. Popping the latest opener

```asm
DEC TOP_INDEX
XOR BX, BX
MOV BL, TOP_INDEX
```

Because the count denotes the next free index, decrementing it produces
the index of the item being removed.

For a stack with three entries:

```text
before pop: count = 3, top item at index 2
after DEC:  count = 2, BX = 2
```

The removed byte can now be examined at `BRACKET_STACK[BX]`.

## 31. Comparing the actual and expected opener

```asm
CMP BRACKET_STACK[BX], DL
JNE NON_BALANCED
```

The memory byte is the most recent unmatched opener.
`DL` is the opener required by the current closing bracket.

Equal types mean that this pair matches.
Different types immediately reject the whole input.

The code does not search deeper in the stack for a convenient opener.
Doing that would accept crossed nesting incorrectly.

## 32. Why decrement before comparing is acceptable

The source reduces `TOP_INDEX` before checking the popped byte's type.
If the types mismatch, the logical stack has already changed.

That does not affect this program's result because it immediately jumps to
`NON_BALANCED` and never resumes the scan.

If this were a reusable parser that recovered from errors, it might need
to preserve or restore more state. This program performs a single final
accept-or-reject decision.

## 33. Consuming a successfully handled character

```asm
CHARACTER_DONE:
    INC SI
    LOOP CHECK_NEXT_CHARACTER
```

An opening bracket reaches this point after a push.
A matching closing bracket reaches it after a pop.

Every successful iteration advances the input pointer by one byte and
reduces the remaining-character count by one.

An invalid character or mismatch jumps directly to the failure path instead.

## 34. Checking for leftover opening brackets

When the character count reaches zero, execution falls through to:

```asm
CHECK_STACK_EMPTY:
    CMP TOP_INDEX, 0
    JNE NON_BALANCED
```

If any openers remain, some closing brackets were missing.

For example:

```text
input: ([]
after scan: stack contains (
result: Non-Balanced
```

Scanning every character without a mismatch is necessary, but not sufficient.
The final empty-stack condition is also required.

## 35. Printing Balanced

```asm
BALANCED:
    LEA DX, BALANCED_TEXT
    CALL PRINT_STRING
    JMP EXIT_PROGRAM
```

The explicit jump skips the failure-message code immediately below.

Without that jump, the success path would fall through and print
`Non-Balanced` as well.

## 36. Printing Non-Balanced

```asm
NON_BALANCED:
    LEA DX, NOT_BAL_TEXT
    CALL PRINT_STRING
```

All failure causes share this message:

```text
invalid character
closing bracket with empty stack
mismatched bracket types
stack capacity failure
leftover openers at end
```

The program does not print a detailed error reason and does not prompt again.

## 37. Both outcomes use the same exit status

```asm
EXIT_PROGRAM:
    MOV AX, 4C00H
    INT 21H
```

DOS function `4CH` terminates the program.
`AL = 0` is returned for **both** balanced and non-balanced inputs.

The printed text carries the bracket-check result.
A script checking only the process exit status could not distinguish them.

`END MAIN` at the end of the file identifies the program entry point;
it is not the executed exit instruction.

## 38. PRINT_STRING in full

```asm
PRINT_STRING PROC NEAR
    PUSH AX
    MOV AH, 09H
    INT 21H
    POP AX
    RET
PRINT_STRING ENDP
```

Input: `DS:DX` points to a `$`-terminated message.

The helper saves `AX` before changing `AH` to select DOS service `09H`.
It restores `AX` before returning.

`NEAR` means the procedure is called within the current code segment.
The near return address is an offset on the CPU stack.

## 39. Why the input is not printed through PRINT_STRING

The DOS input buffer is length-counted and contains a carriage return.
It is not prepared as a `$`-terminated message.

Passing it directly to `PRINT_STRING` would not be a correct way to display
the entered line.

The source instead uses fixed messages for output.
Input echo is provided by the buffered DOS input service.

## 40. Register roles during the scan

| Register or variable | Role |
| --- | --- |
| `DS` | Segment containing input, messages, and software stack |
| `SI` | Pointer to current input character |
| `CX` | Characters remaining, including the current iteration before LOOP |
| `AL` | Current ASCII character |
| `DL` | Expected opener when handling a closer |
| `BX` | Zero-extended software-stack array index |
| `TOP_INDEX` | Number of unmatched opening brackets |
| `SS:SP` | CPU stack used by procedure calls and saved registers |

Roles can change between phases. For example, `DX` is a message pointer
during printing but `DL` is an expected bracket during matching.

## 41. A complete balanced trace: { [ ( ) ] }

For the actual input `{[()]}` without spaces:

| Step | Character | Action | Stack, bottom to top | TOP_INDEX |
| ---: | --- | --- | --- | ---: |
| 0 | — | Initialize | Empty | 0 |
| 1 | `{` | Push | `{` | 1 |
| 2 | `[` | Push | `{ [` | 2 |
| 3 | `(` | Push | `{ [ (` | 3 |
| 4 | `)` | Pop `(`, matches | `{ [` | 2 |
| 5 | `]` | Pop `[`, matches | `{` | 1 |
| 6 | `}` | Pop `{`, matches | Empty | 0 |

The final count is zero, so the program prints `Balanced`.

Spaces in the table separate stack items for readability; they are not input.

## 42. Register trace for one closing bracket

Suppose the current stack contains `'('`, `'['` and the current input is `']'`.

```text
Before dispatch:
    AL = ']'
    TOP_INDEX = 2

CHECK_SQUARE:
    DL = '['

CHECK_CLOSING:
    TOP_INDEX != 0
    TOP_INDEX becomes 1
    BX becomes 0001H
    BRACKET_STACK[1] = '['
    compare '[' with '[' → equal

CHARACTER_DONE:
    SI advances
    CX decreases
```

The remaining logical stack contains only `'('`.

## 43. Crossed nesting trace: ([)]

```text
Read '(' → push '(' → stack: (
Read '[' → push '[' → stack: ( [
Read ')' → expected opener is '('
           pop actual opener '['
           '[' != '(' → Non-Balanced
```

The program fails at the third character.
It does not continue to the final `']'`.

Although the stack contains a `'('` deeper down, using it would cross the
still-open square bracket and violate proper nesting.

## 44. Underflow trace: ())

```text
Read '(' → push → count 1
Read ')' → matching pop → count 0
Read ')' → count is already 0 → Non-Balanced
```

The empty-stack check prevents a decrement from zero.
This failure is called stack **underflow**: attempting to remove an item
when none exists.

## 45. Leftover opener trace: ([]

```text
Read '(' → stack: (
Read '[' → stack: ( [
Read ']' → matching pop → stack: (
End input → TOP_INDEX = 1 → Non-Balanced
```

There was no bad closing bracket during the scan.
The failure is discovered only by the final stack-empty test.

That explains why the last test cannot be omitted.

## 46. Consecutive balanced groups

For `()[]{}`:

```text
'(' → push    ')' → pop → empty
'[' → push    ']' → pop → empty
'{' → push    '}' → pop → empty
```

The stack can become empty before the input ends.
That is allowed: the next opening bracket begins another balanced group.

During the scan, an empty stack causes failure only when the current character
is a closer. At the end of the scan, the stack must be empty for success.

## 47. Empty input

For a line containing no characters:

```text
DOS returns length = 0
TOP_INDEX is initialized to 0
JCXZ branches to CHECK_STACK_EMPTY
the stack is empty
Balanced is printed
```

There is no “must contain at least one bracket” validation in this source.

If an assignment specification required nonempty input, that would be a
different requirement from the behavior implemented here.

## 48. Maximum input and maximum nesting

The accepted input buffer can hold 80 characters.
The software stack has 80 entries.

A line of 80 opening brackets fills the stack without an out-of-bounds write,
but it is rejected at the end because none have closed.

A balanced line containing 40 opening brackets followed by their 40 matching
closers reaches depth 40 and uses all 80 input characters.

The maximum nesting depth of a balanced sequence within this input limit
is therefore 40, although the stack array itself has capacity 80.

## 49. What happens to extra typed characters?

The input length limit is imposed by DOS buffered input, not by a scan that
reads an arbitrarily long line and reports its excess length.

Under normal DOS line editing, extra keystrokes after the input buffer is
full are not appended to the stored text. The checker sees the returned
buffer contents only.

Do not claim that the program explicitly diagnoses an overlong original
keystroke sequence. It has no separate message for that condition.

## 50. Why one pass is enough

When the scanner reaches a closing bracket, the correct opener must be the
most recent unmatched one.

Earlier successfully processed pairs cannot need reconsideration: their
types and local nesting have already been checked.

The stack preserves exactly the information the next character may need.
No backtracking through previous input is required.

## 51. The stack invariant

After every successfully processed prefix of the line:

```text
BRACKET_STACK[0 .. TOP_INDEX-1]
contains exactly the unmatched opening brackets,
in the order they appeared in that prefix.
```

This statement is the algorithm's **invariant**: a property maintained
throughout the scan.

Pushing an opener extends that unmatched list.
Matching a closer removes exactly its final item.
Any other situation fails immediately.

## 52. Why the final condition proves balance

If the program reaches the end without failure:

```text
every input character was a recognized bracket;
every closer had an available opener;
every closer matched the most recent unmatched opener.
```

If the stack is also empty, every opener has been matched.
Together these conditions establish balance and proper nesting.

An empty stack alone would not prove validity if mismatches had been ignored.
The early failure checks and final test work together.

## 53. Time and space requirements

For an input of length `n`:

```text
Time: O(n)
Maximum logical stack storage: O(n)
```

Every successfully processed character performs a fixed number of comparisons
and at most one push or pop.

The concrete implementation reserves a fixed 80-byte stack because its input
size is bounded. Its CPU-stack use for the printing helper is also bounded.

An invalid line can terminate early, before scanning all `n` characters.

## 54. C-like equivalent

```c
unsigned char stack[80];
unsigned int top = 0;
bool balanced = true;

for (i = 0; i < input_length; i++) {
    char ch = input[i];

    if (ch == '(' || ch == '{' || ch == '[') {
        if (top >= 80) {
            balanced = false;
            break;
        }
        stack[top] = ch;
        top++;
        continue;
    }

    char expected;
    if (ch == ')')      expected = '(';
    else if (ch == '}') expected = '{';
    else if (ch == ']') expected = '[';
    else {
        balanced = false;
        break;
    }

    if (top == 0) {
        balanced = false;
        break;
    }

    top--;
    if (stack[top] != expected) {
        balanced = false;
        break;
    }
}

if (top != 0)
    balanced = false;

print(balanced ? "Balanced" : "Non-Balanced");
return 0;  // matches the source's exit status for both outcomes
```

This pseudocode describes the algorithm after the bounded DOS input step.
It does not introduce whitespace skipping or recovery absent from the assembly.

## 55. The key instructions and flags

| Instruction | Purpose here |
| --- | --- |
| `MOV AL, [SI]` | Load the current character |
| `CMP` | Test a character, count, or matching opener |
| `JE` | Branch on equality, `ZF = 1` |
| `JNE` | Branch on inequality, `ZF = 0` |
| `JAE` | Reject unsigned count at or above capacity, `CF = 0` |
| `JCXZ` | Skip the scan when the register `CX` is zero |
| `INC TOP_INDEX` | Grow the logical software stack |
| `DEC TOP_INDEX` | Remove its latest item |
| `INC SI` | Advance to the next input byte |
| `LOOP` | Decrement `CX` and repeat while nonzero |

`JE` and `JNE` read flags set by the immediately relevant `CMP`.
`JCXZ` reads the counter directly, and `LOOP` does not change arithmetic flags.

## 56. Important 8085 comparisons

| Familiar idea | 8085 | This 8086 source |
| --- | --- | --- |
| Current byte | `A` | `AL` |
| Input pointer | Often `HL` | `SI`, using data segment `DS` |
| Byte load | `MOV A, M` | `MOV AL, [SI]` |
| Pointer advance | `INX H` | `INC SI` |
| Equality branch | `JZ`/`JNZ` after comparison | `JE`/`JNE` after `CMP` |
| Counted loop | Counter decrement and branch | `LOOP` with `CX` |
| Procedure call | `CALL` and `RET` | Near `CALL` and `RET` |
| Software stack | Array and managed pointer/count | `BRACKET_STACK` and `TOP_INDEX` |

The stack algorithm transfers directly between processors.
The addressing syntax, register sizes, segment model, and DOS interface differ.

## 57. Common misunderstandings

**“TOP_INDEX points at the top occupied item.”**

It holds the count and next free index. The occupied top is at count minus one.

**“The program uses PUSH and POP for each bracket.”**

It uses ordinary array writes and count updates. CPU `PUSH`/`POP` are used
in the printing helper for saving `AX`.

**“Equal numbers of openers and closers are enough.”**

Bracket types and nesting order must match as well.

**“Spaces are harmless.”**

This implementation rejects every non-bracket character, including spaces.

**“The exit code says whether brackets are balanced.”**

Both outcomes return zero. The displayed message supplies the result.

## 58. Cases you should be able to predict

| Input | Result | Reason |
| --- | --- | --- |
| Empty line | Balanced | No unmatched brackets |
| `()` | Balanced | One matching pair |
| `[]{}()` | Balanced | Consecutive matching groups |
| `{[()]}` | Balanced | Properly nested types |
| `([)]` | Non-Balanced | Crossed nesting |
| `]` | Non-Balanced | Closer with empty stack |
| `((` | Non-Balanced | Leftover openers |
| `{]` | Non-Balanced | Incorrect bracket type |
| `( )` | Non-Balanced | Space is rejected |
| `(a)` | Non-Balanced | Ordinary letters are rejected |

These outcomes follow from the source logic; they are not a claim of a new
interactive DOSBox test run.

## 59. The part to study most carefully

The push operation is:

```asm
MOV BRACKET_STACK[BX], AL
INC TOP_INDEX
```

The closing-bracket operation is:

```asm
CMP TOP_INDEX, 0
JE NON_BALANCED
DEC TOP_INDEX
XOR BX, BX
MOV BL, TOP_INDEX
CMP BRACKET_STACK[BX], DL
JNE NON_BALANCED
```

Understand why the write precedes the increment for push, while the decrement
precedes the read for pop. Those two ordering decisions implement the same
count-based stack convention.

## 60. An exam-ready explanation

The program reads up to 80 bracket characters using DOS buffered input.
It scans them from left to right with `SI`, using `CX` as the character count.
An opening bracket is stored in an array-based stack and increments its count.
A closing bracket requires a nonempty stack; the most recent opener is removed
and compared with the type required by that closer.

An unknown character, missing opener, or type mismatch immediately prints
`Non-Balanced`. After the scan, any remaining opener also causes failure.
If the scan succeeds and the stack is empty, it prints `Balanced`.
The algorithm is linear in the input length and enforces proper nesting
through the stack's Last In, First Out order.
