```asm
OPERAND2 DW 0

    CMP AL, '-'

    CMP AL, '*'
    JE Q4_MULTIPLY
    CMP AL, '/'
    JE Q4_DIVIDE

    ADD AX, OPERAND2

    CALL PRINT_STRING
    CALL PRINT_UINT
    CALL PRINT_NEWLINE

    CALL PRINT_STRING

    CMP AX, OPERAND2

    MOV DL, '-'
    CALL PRINT_CHAR

    SUB AX, OPERAND1
    JMP SHORT Q4_SUB_PRINT

    SUB AX, OPERAND2
Q4_SUB_PRINT:

    CALL PRINT_NEWLINE
    JMP SHORT Q4_EXIT_OK

Q4_MULTIPLY:
    MOV AX, OPERAND1
    MOV BX, OPERAND2
    MUL BX
    LEA DX, RESULT_LABEL
    CALL PRINT_STRING
    CALL PRINT_UINT

    JMP SHORT Q4_EXIT_OK

Q4_DIVIDE:

    JE Q4_DIVIDE_ZERO
    MOV AX, OPERAND1
    XOR DX, DX
    DIV OPERAND2

    MOV REMAINDER, DX

    CALL PRINT_UINT

    CALL PRINT_STRING
    MOV AX, REMAINDER
    CALL PRINT_UINT
    CALL PRINT_NEWLINE

    LEA DX, INVALID_OPERATOR
    CALL PRINT_STRING
    JMP SHORT Q4_EXIT_ERROR
Q4_DIVIDE_ZERO:

Q4_EXIT_OK:

; Accepts 1 to 3 decimal digits, rejects non-digits and values above 255.
; Returns: AX = value and CF clear, or CF set for invalid input.
; Preserves: BX, CX, DX, SI, and DI.

    PUSH CX
    PUSH DX
    PUSH SI
    PUSH DI

    MOV AH, 0AH
    INT 21H

    JZ RB_BAD
    CMP CX, 3
    JA RB_BAD

RO_DONE:

    POP DX
    POP CX

    INT 21H
```

Question 4 brings several ideas together: **validated input, operator selection, branching, signed-looking subtraction using unsigned values, 16-bit multiplication, division with quotient/remainder, and reusable procedures**. This is basically your first small interactive MASM program. 🔥

The calculator accepts two operands from `0` to `255`, then one of:

```text
+
-
*
/
```

and performs the operation.

The main logic is much more important than the input helper procedures, so focus especially on the operation-selection section and the four arithmetic blocks.

## 1. Why operands are stored as `DW`

You have:

```asm
OPERAND1 DW 0
OPERAND2 DW 0
```

`DW` means:

```text
Define Word
```

so each operand gets 16 bits.

You might wonder:

> But input is only 0–255. Why not `DB`?

Because later results can be larger than 255.

For example:

```text
255 + 255 = 510
255 × 255 = 65025
```

Both fit in 16 bits.

So storing the operands as words makes later arithmetic easier.

---

## 2. Reading the first operand

```asm
LEA DX, FIRST_PROMPT
CALL PRINT_STRING
CALL READ_BYTE
JNC FIRST_OK
JMP BAD_INPUT
```

`READ_BYTE` returns:

```text
AX = entered number
CF = 0 if valid
CF = 1 if invalid
```

Then:

```asm
JNC FIRST_OK
```

means:

```text
Jump if No Carry
```

so valid input continues.

---

## 3. Why `XOR AH, AH`?

```asm
FIRST_OK:
    XOR AH, AH
    MOV OPERAND1, AX
```

The intended input is one byte:

```text
0–255
```

That value belongs in `AL`.

To make sure the complete 16-bit register contains the same unsigned value, we clear `AH`:

```text
AH = 00H
AL = input
```

Example:

```text
input = 200 = C8H

AX = 00C8H
```

Then:

```asm
MOV OPERAND1, AX
```

stores the 16-bit value.

This operation is called **zero extension**:

```text
8-bit unsigned value
C8H
↓
16-bit unsigned value
00C8H
```

Very important concept.

---

## 4. Reading the operator

```asm
CALL READ_OPERATOR
```

This procedure accepts exactly one character:

```text
+
-
*
/
```

If valid, it returns:

```text
AL = operator
CF = 0
```

Then:

```asm
MOV OPERATOR, AL
```

stores that ASCII character.

So if the user enters:

```text
*
```

then:

```text
OPERATOR = ASCII '*'
```

# 5. Operation selection

After both operands are read:

```asm
MOV AL, OPERATOR

CMP AL, '+'
JE Q4_ADD

CMP AL, '-'
JE Q4_SUBTRACT

CMP AL, '*'
JE Q4_MULTIPLY

CMP AL, '/'
JE Q4_DIVIDE

JMP BAD_OPERATOR
```

This is basically an assembly-language version of:

```c
switch (operator) {
    case '+':
        ...
    case '-':
        ...
    case '*':
        ...
    case '/':
        ...
}
```

There is no high-level `switch`, so the program repeatedly compares.

---

# 6. `JE`

You have already seen `CMP`.

```asm
CMP AL, '+'
```

checks whether:

```text
AL == '+'
```

Then:

```asm
JE Q4_ADD
```

means:

```text
Jump if Equal
```

Internally, `CMP` sets the Zero Flag if the two values are equal.

So:

```text
CMP → modifies flags
JE  → examines Zero Flag
```

This is the same general pattern you learned in Question 2.

# 7. Addition

The addition block is simple:

```asm
Q4_ADD:
    MOV AX, OPERAND1
    ADD AX, OPERAND2
```

Suppose:

```text
OPERAND1 = 200
OPERAND2 = 100
```

Then:

```text
AX = 200
AX = AX + 100
AX = 300
```

Because AX is 16-bit, `300` fits easily.

This is one reason the program doesn't calculate only with AL.

If you had used 8-bit arithmetic:

```text
200 + 100 = 300
```

which exceeds 255.

# 8. Printing the result

```asm
LEA DX, RESULT_LABEL
CALL PRINT_STRING
CALL PRINT_UINT
```

`PRINT_UINT` assumes:

```text
AX = unsigned 16-bit number
```

and prints it as decimal.

So if:

```text
AX = 510
```

it prints:

```text
510
```

---

# 9. Subtraction is more interesting

The user may enter:

```text
20 - 50
```

Mathematically:

```text
20 - 50 = -30
```

But `OPERAND1` and `OPERAND2` are unsigned.

So the program handles the sign manually.

The block is:

```asm
Q4_SUBTRACT:
    LEA DX, RESULT_LABEL
    CALL PRINT_STRING

    MOV AX, OPERAND1
    CMP AX, OPERAND2
    JAE Q4_SUB_POSITIVE
```

---

# 10. What is `JAE`?

`JAE` means:

```text
Jump if Above or Equal
```

for **unsigned comparison**.

So:

```asm
CMP AX, OPERAND2
JAE Q4_SUB_POSITIVE
```

means:

```text
if OPERAND1 >= OPERAND2
    result is non-negative
```

Remember the unsigned jump family:

```text
JB   → below
JBE  → below or equal
JA   → above
JAE  → above or equal
```

This is the unsigned equivalent of comparing normal positive numbers.

---

# 11. Negative subtraction case

If:

```text
OPERAND1 < OPERAND2
```

then execution continues:

```asm
MOV DL, '-'
CALL PRINT_CHAR
```

So it prints the minus sign manually.

Then:

```asm
MOV AX, OPERAND2
SUB AX, OPERAND1
```

Notice it calculates the magnitude in reverse:

```text
larger - smaller
```

For:

```text
20 - 50
```

the program does:

```text
print '-'

50 - 20 = 30
```

so the output becomes:

```text
-30
```

This avoids dealing with signed 16-bit arithmetic internally.

Very neat.

---

# 12. Positive subtraction case

If:

```text
OPERAND1 >= OPERAND2
```

it jumps here:

```asm
Q4_SUB_POSITIVE:
    SUB AX, OPERAND2
```

Remember AX already contains `OPERAND1`.

So:

```text
AX = OPERAND1 - OPERAND2
```

Example:

```text
80 - 25 = 55
```

---

# 13. Multiplication

```asm
Q4_MULTIPLY:
    MOV AX, OPERAND1
    MOV BX, OPERAND2
    MUL BX
```

This uses 16-bit unsigned multiplication.

For:

```asm
MUL BX
```

the CPU performs:

```text
AX × BX → DX:AX
```

This is crucial.

The result can theoretically be 32-bit.

But your operands are at most 255:

```text
255 × 255 = 65025
```

and:

```text
65025 = FE01H
```

which fits entirely inside AX.

So in this particular calculator:

```text
DX = 0000H
AX = result
```

for every valid multiplication.

Then:

```asm
CALL PRINT_UINT
```

prints AX.

---

# 14. Why `DX:AX`?

8086 multiplication is designed so that multiplication never has to discard the upper half automatically.

For 16-bit operands:

```text
FFFFH × FFFFH
```

could need up to 32 bits.

So x86 returns:

```text
DX = upper 16 bits
AX = lower 16 bits
```

Written as:

```text
DX:AX
```

Think:

```text
DX       AX
high     low
16 bits  16 bits
```

Together they form one 32-bit product.

For your input range, though, AX alone is sufficient.

---

# 15. Division by zero check

Before dividing:

```asm
CMP OPERAND2, 0
JE Q4_DIVIDE_ZERO
```

This is essential.

Division by zero is invalid and causes a CPU exception.

So the program checks first:

```text
if second operand == 0:
    show error
```

Never blindly execute `DIV` when the divisor might be zero.

---

# 16. Division setup

```asm
MOV AX, OPERAND1
XOR DX, DX
DIV OPERAND2
```

For a 16-bit divisor, `DIV` uses:

```text
DX:AX
```

as the dividend.

So before dividing a normal 16-bit number in AX, you typically do:

```asm
XOR DX, DX
```

to make:

```text
DX:AX = 0000:operand1
```

---

# 17. Division result

For:

```asm
DIV OPERAND2
```

the result is:

```text
AX = quotient
DX = remainder
```

Example:

```text
17 / 5
```

gives:

```text
AX = 3
DX = 2
```

because:

```text
17 = 3 × 5 + 2
```

This relation is worth remembering:

```text
dividend = quotient × divisor + remainder
```

---

# 18. Why save quotient and remainder?

Immediately after division:

```asm
MOV QUOTIENT, AX
MOV REMAINDER, DX
```

because subsequent printing routines may alter registers.

So now:

```text
QUOTIENT = quotient
REMAINDER = remainder
```

and they can safely be loaded later.

---

# 19. Division output

```asm
LEA DX, QUOTIENT_LABEL
CALL PRINT_STRING

MOV AX, QUOTIENT
CALL PRINT_UINT
```

prints the quotient.

Then:

```asm
LEA DX, REMAINDER_LABEL
CALL PRINT_STRING

MOV AX, REMAINDER
CALL PRINT_UINT
```

prints the remainder.

Example:

```text
First operand: 17
Operator: /
Second operand: 5

Quotient: 3  Remainder: 2
```

# 20. The most important arithmetic rules so far

For x86, memorize these operand/result rules:

| Instruction | Operation |
|---|---|
| `ADD AX, BX` | `AX = AX + BX` |
| `SUB AX, BX` | `AX = AX - BX` |
| `MUL BL` | `AL × BL → AX` |
| `MUL BX` | `AX × BX → DX:AX` |
| `DIV BL` | `AX ÷ BL → AL quotient, AH remainder` |
| `DIV BX` | `DX:AX ÷ BX → AX quotient, DX remainder` |

Your program uses the 16-bit forms for multiplication and division.

---

# 21. Why multiplication input doesn't need `XOR DX,DX`

Before:

```asm
MUL BX
```

you do not need:

```asm
XOR DX, DX
```

because `MUL BX` only takes its input from:

```text
AX and BX
```

and writes the result into:

```text
DX:AX
```

DX is an **output**, not part of the input.

Division is different:

```asm
DIV BX
```

takes the dividend from:

```text
DX:AX
```

so DX must be prepared correctly.

This distinction is very important.

# 22. `READ_BYTE` is the same decimal conversion idea

This section:

```asm
MOV AX, BX
MOV DX, 10
MUL DX
ADD AX, DI
```

calculates:

```text
new_value = old_value × 10 + new_digit
```

Example input:

```text
"245"
```

progress:

```text
0
0 × 10 + 2 = 2
2 × 10 + 4 = 24
24 × 10 + 5 = 245
```

Same idea as your earlier programs.

This procedure is very straightforward.

```asm
CMP OPERATOR_BUFFER+1, 1
JNE RO_BAD
```

requires exactly one typed character.

Then:

```asm
MOV AL, OPERATOR_BUFFER+2
```

loads it.

Next:

```asm

JE RO_OK
CMP AL, '-'
JE RO_OK
CMP AL, '*'
JE RO_OK
CMP AL, '/'
JE RO_OK
```

So if any supported operator matches:


Otherwise:


# 25. PRINT_UINT

You've seen this algorithm before, but this version prints a full unsigned 16-bit number.

```asm
MOV BX, 10
XOR CX, CX
```

BX is the divisor, CX counts digits.

Then:

```asm
PU_DIVIDE:
    XOR DX, DX
    DIV BX
    PUSH DX
    INC CX
    OR AX, AX
    JNZ PU_DIVIDE
```

Repeatedly divide by 10.

For:

```text
65025
```

the remainders are:

```text
5
2
0
5
6
```

in reverse order.

They are pushed onto the stack.

Then:

```asm
PU_DIGIT:
    POP DX
    ADD DL, '0'
    MOV AH, 02H
    INT 21H
    LOOP PU_DIGIT
```

pops:

```text
6 5 0 2 5
```

and prints:

```text
65025
```

Classic decimal-conversion algorithm.

# 26. Important detail: printing zero works

Suppose:

```text
AX = 0
```

The loop still executes once:

```asm
DIV BX
```

giving:

```text
quotient = 0
remainder = 0
```

It pushes zero and increments CX once.

Then:

```text

```

converts `0` into ASCII `'0'`.

So:

```text
0
```

prints correctly.

That's a nice property of the implementation.

```asm

```

means:

```text
AH = 4CH → terminate
AL = 01H → error status
```

while:

```asm

```

# 28. Full control-flow structure

You can mentally reduce the whole program to:

```text
read operand1

read operator

read operand2

if operator == '+'
    add

else if operator == '-'
    subtract

else if operator == '*'
    multiply

else if operator == '/'
    if divisor == 0
        error
    else
        divide
```

That's all the main calculator logic is doing.

---

# 29. C-style equivalent

Conceptually:

```c
unsigned int a;
unsigned int b;
char op;

if (op == '+') {
    result = a + b;
}
else if (op == '-') {
    if (a >= b)
        print(a - b);
    else
        print(-(int)(b - a));
}
else if (op == '*') {
    result = a * b;
}
else if (op == '/') {
    if (b == 0)
        error;
    else {
        quotient = a / b;
        remainder = a % b;
    }
}
```

That makes the MASM branching much easier to understand.

# 30. Mapping C logic to MASM

For example:

```c
if (a >= b)
```

becomes:

```asm
CMP AX, OPERAND2

```

And:

```c
if (b == 0)
```

becomes:

```asm

JE Q4_DIVIDE_ZERO
```

And:

```c
if (op == '*')
```

becomes:

```asm
CMP AL, '*'
JE Q4_MULTIPLY
```

Assembly is mostly high-level control flow broken into:

```text
compare
↓
conditional jump
```

```asm
MUL BX
```

produces:

```text
DX:AX = 0000:FE01H
```

and:

```text
FE01H = 65025 decimal
```

Output:

```text
Result: 65025
```

This demonstrates exactly why a 16-bit result is useful.

---

# 34. Example: `19 / 4`

Before division:

```text
AX = 19
DX = 0
```

Then:

```asm
DIV OPERAND2
```

with divisor `4`.

CPU produces:

```text
AX = 4
DX = 3
```

because:

```text
19 = 4 × 4 + 3
```

Output:

```text
Quotient: 4  Remainder: 3
```

# 35. Example: `19 / 0`

Before `DIV`, the program checks:

```asm
CMP OPERAND2, 0
JE Q4_DIVIDE_ZERO
```

So `DIV` never executes.

Instead:

```text
ERROR: division by zero.
```

is printed.

Correct and necessary.

# 36. New concepts introduced by Question 4

The main new things are:

| Concept | Meaning |
|---|---|
| zero extension | turn an 8-bit unsigned value into a 16-bit value |
| `JE` | jump if equal |
| `JAE` | unsigned above-or-equal |
| operator dispatch | select code based on a typed operator |
| `MUL BX` | 16-bit multiplication into `DX:AX` |
| `DIV word` | divide `DX:AX`, quotient in AX, remainder in DX |
| manual negative display | print `-` and calculate magnitude |
| divide-by-zero check | must happen before `DIV` |

# 37. The two most important register rules here

If you remember only two arithmetic rules from this problem, remember these:

```text
MUL 16-bit operand:
AX × operand → DX:AX
```

and:

```text
DIV 16-bit operand:
DX:AX ÷ operand
→ AX = quotient
→ DX = remainder
```

That distinction appears everywhere in 8086/x86 assembly.

---

# 38. Connection to your 8085 knowledge

8085 does not have native general multiplication/division instructions like this.

You usually implement multiplication through repeated addition or shifts, and division through repeated subtraction or similar algorithms.

8086 gives you:

```asm
MUL
DIV
```

directly.

So a major improvement over 8085 is that arithmetic operations that previously required loops can become one CPU instruction.

# 39. The core of Question 4 to study

Don't spend most of your time memorizing `READ_BYTE`.

The main assignment logic is essentially:

```asm
MOV AL, OPERATOR

CMP AL, '+'
JE Q4_ADD
CMP AL, '-'
JE Q4_SUBTRACT
CMP AL, '*'
JE Q4_MULTIPLY
CMP AL, '/'
JE Q4_DIVIDE
```

followed by:

```asm
Q4_ADD:
    MOV AX, OPERAND1
    ADD AX, OPERAND2
```

```asm
Q4_SUBTRACT:
    MOV AX, OPERAND1
    CMP AX, OPERAND2
    JAE ...
```

```asm
Q4_MULTIPLY:
    MOV AX, OPERAND1
    MOV BX, OPERAND2
    MUL BX
```

```asm
Q4_DIVIDE:
    CMP OPERAND2, 0
    JE ...
    MOV AX, OPERAND1
    XOR DX, DX
    DIV OPERAND2
```

If you can explain those four blocks confidently, you've understood the important MASM content of this question.

At this point, your progression is:

```text
Q1 → memory + arithmetic + loops

Q3 → bits + hex + ASCII
Q4 → full arithmetic + branching + MUL/DIV
```

You're now past the very basic MASM stage—you've already encountered most of the core 8086 instructions that typically appear in introductory lab problems.
