# Question 3 — FCFS disk scheduling

Source: [Q3.ASM](../Q3.ASM).

The program reads a list of cylinder requests, reads the initial disk-head
position, then visits the requests in exactly their entered order. At each
step it adds the distance travelled to a running total.

If you know 8085, the main algorithm is already within reach: traverse an array,
compare two numbers, subtract the smaller from the larger, and accumulate the
result. The new 8086 details are word arrays, segment-based addressing, native
multiplication/division for decimal I/O, and procedures that preserve loop state.

---

## 1. What FCFS means here

FCFS stands for **First-Come-First-Served**.

Suppose requests arrive in this order:

```text
98, 183, 37
```

They are serviced in that same order:

```text
98 → 183 → 37
```

The program does not sort them and does not choose the nearest pending request.
That would be a different scheduling policy.

The entered list is the arrival order. No real disk hardware is moved; the
program calculates a scheduling example numerically.

---

## 2. Distance is an absolute difference

For current head position `h` and next request `r`:

```text
movement = |h − r|
```

For example:

```text
h = 53, r = 98  → movement = 45
h = 98, r = 183 → movement = 85
h = 183, r = 37 → movement = 146
```

The implementation chooses a subtraction direction so the answer is always
nonnegative. It does not compute a signed negative value and then call an
absolute-value routine.

---

## 3. Complete program flow

`MAIN` is the executable entry procedure. It performs the input phases and
the FCFS traversal, then terminates through DOS.

```text
initialize DS
print title
read valid request count, 1..10
read that many valid cylinder requests
read valid initial head position
set current head = initial head; total = 0
print initial head
for every request in stored order:
    print arrow
    calculate absolute difference
    add difference to total
    update current head to that request
    print the request
print total movement and units
terminate
```

Input errors retry only the current field. They do not discard the already
accepted request list.

---

## 4. Stack and segment declarations

```asm
STACKSEG SEGMENT PARA STACK 'STACK'
    DW 128 DUP (?)
STACKSEG ENDS
```

This reserves 128 words, or 256 bytes, for calls and saved registers.

`DATASEG` holds messages, input storage, the request array, and scheduling
variables. `CODESEG` holds instructions.

```asm
ASSUME CS:CODESEG, DS:DATASEG, SS:STACKSEG
```

is assembler information. Actual data-register initialization is:

```asm
MOV AX, DATASEG
MOV DS, AX
```

The first `MOV` obtains the segment value and the second loads `DS`. Ordinary
references such as `CURRENT_HEAD` and `REQUESTS[SI]` then access the data segment.

---

## 5. Why cylinders are stored as words

```asm
REQUEST_COUNT  DB 0
REQUESTS       DW 10 DUP (0)
INITIAL_HEAD   DW 0
CURRENT_HEAD   DW 0
TOTAL_MOVEMENT DW 0
```

The count is at most ten, so one byte is enough.

A cylinder may be as large as 999:

```text
maximum unsigned byte = 255
999 > 255
```

Therefore each cylinder uses a 16-bit word. The request array has:

```text
10 × 2 = 20 bytes
```

In 8085 you would similarly need two bytes or a register pair for a value above
255. Here `AX`, `BX`, and memory words let the CPU operate on all 16 bits at once.

---

## 6. Initial and current head are different variables

`INITIAL_HEAD` retains the starting cylinder for the first item in the printed
sequence.

`CURRENT_HEAD` changes after each request is serviced.

For head 53 and requests 98, 183:

| Stage | INITIAL_HEAD | CURRENT_HEAD |
| --- | --- | --- |
| Before scheduling | 53 | 53 |
| After request 98 | 53 | 98 |
| After request 183 | 53 | 183 |

Keeping the original and working state separate makes the output and
calculation roles explicit.

---

## 7. The DOS number-input buffer

```asm
INPUT_BUFFER DB 4,0,4 DUP (0)
```

The first byte is the DOS buffered-input capacity, including carriage-return
capacity. The second receives the actual entered-character count excluding CR.
The character area begins two bytes after the label.

The configured buffer accommodates up to three typed decimal characters plus
CR:

```text
INPUT_BUFFER[0] → 4
INPUT_BUFFER[1] → returned length
INPUT_BUFFER[2] → digit 1
INPUT_BUFFER[3] → digit 2
INPUT_BUFFER[4] → digit 3
INPUT_BUFFER[5] → CR for a three-character entry
```

This is a DOS line buffer, unlike Question 1's manually filled password array.

---

## 8. Read the request count

```asm
LEA DX, COUNT_MSG
CALL PRINT_STRING
CALL READ_NUMBER
JC BAD_COUNT
```

`READ_NUMBER` has this interface:

```text
valid decimal input → AX = value, CF = 0
invalid input       → CF = 1; AX is not a valid returned result
```

`JC` means “jump if carry is set.” It immediately tests the status returned
by the input helper.

Your 8085 connection is direct: subroutines can also use carry as a status
flag, followed by an 8085 `JC` or `JNC` in the caller.

---

## 9. Validate the count's meaning

```asm
CMP AX, 1
JB BAD_COUNT
CMP AX, 10
JA BAD_COUNT
MOV REQUEST_COUNT, AL
```

Parsing a number and checking its allowed application range are different
tasks. `123` is a valid decimal number but an invalid request count.

`JB` and `JA` use unsigned comparisons, matching the nonnegative input format.

`AX` has already been constrained to 1 through 10, so storing just `AL` loses
no information.

The error branch prints the invalid-input message and jumps back to `READ_COUNT`.

---

## 10. Why reject zero requests?

This implementation requires at least one request by its interface.

It also starts its later loops with `LOOP`, which decrements `CX` and repeats
while nonzero. Entering such a loop body with `CX=0` would not mean “skip the
loop”; after decrement it would wrap to `FFFFH`.

The count-validation step ensures the loops are entered with a count from
1 through 10.

The general rule is:

```text
if a counted loop must support zero iterations, check before its first body
```

Here the accepted input range makes zero iterations unnecessary.

---

## 11. Prepare the word-array input loop

```asm
XOR SI, SI
XOR CX, CX
MOV CL, REQUEST_COUNT
```

`SI` is a byte offset relative to the start of `REQUESTS`.

`CX` is the remaining number of successful entries to collect.

Clearing the whole `CX` before loading `CL` prevents an old high byte `CH` from
becoming part of the loop count.

```text
REQUEST_COUNT = 3
CX after initialization = 0003H
```

---

## 12. Store one accepted request

```asm
CALL READ_NUMBER
JC BAD_REQUEST
CMP AX, 999
JA BAD_REQUEST
MOV REQUESTS[SI], AX
ADD SI, 2
LOOP READ_ONE_REQUEST
```

`MOV REQUESTS[SI],AX` is a word store because `AX` is 16-bit and the array is
declared with `DW`.

The next word begins two bytes later:

```text
SI = 0 → request 0
SI = 2 → request 1
SI = 4 → request 2
```

Using `INC SI` would advance only one byte, causing overlapping stores rather
than selecting the next array element.

---

## 13. A word-array memory example

If the entered requests are 98, 183, and 37, their hexadecimal word values are:

```text
98  = 0062H
183 = 00B7H
37  = 0025H
```

x86 stores words little-endian:

| Byte offset from REQUESTS | Stored byte |
| --- | --- |
| 0 | `62H` |
| 1 | `00H` |
| 2 | `B7H` |
| 3 | `00H` |
| 4 | `25H` |
| 5 | `00H` |

The CPU still loads each pair as one word when executing a word-sized `MOV`.

8085 also stores the low byte first in familiar two-byte address/data operations,
but its general arithmetic instructions do not all operate on 16-bit operands
as directly as these 8086 instructions do.

---

## 14. Invalid requests do not consume a slot

At `BAD_REQUEST`, the code prints an error and jumps back to
`READ_ONE_REQUEST`.

It does not execute:

```asm
ADD SI, 2
LOOP READ_ONE_REQUEST
```

on the failed path.

Thus both the array offset and remaining count remain unchanged. The user
re-enters the same request position.

This depends on `READ_NUMBER` preserving the caller's `SI` and `CX`, even though
it uses both internally during decimal conversion.

---

## 15. Read the initial head and reset the total

After all requests have been collected:

```asm
CALL READ_NUMBER
JC BAD_HEAD
CMP AX, 999
JA BAD_HEAD
MOV INITIAL_HEAD, AX
MOV CURRENT_HEAD, AX
MOV TOTAL_MOVEMENT, 0
```

`BAD_HEAD` retries only the initial-head field. The request array is preserved.

Starting both head variables at the accepted value establishes the first leg
of the schedule. Clearing the total ensures that the answer is computed from
the beginning, not added to an old memory value.

---

## 16. Print the sequence's starting point

```asm
LEA DX, SEQUENCE_MSG
CALL PRINT_STRING
MOV AX, INITIAL_HEAD
CALL PRINT_NUMBER
```

The initial head is printed before any request or arrow:

```text
Seek sequence: 53
```

After the loop it might become:

```text
Seek sequence: 53 -> 98 -> 183 -> 37
```

With `n` requests, the displayed sequence therefore contains `n+1` numeric
positions: the origin plus the `n` requests.

---

## 17. Reset traversal state for scheduling

```asm
XOR SI, SI
XOR CX, CX
MOV CL, REQUEST_COUNT
```

The earlier input loop already advanced `SI` past the entered requests and
decremented its own `CX` to zero.

Scheduling must start again at the first array element with the full count.

Reusing a register for a second phase is common in assembly. It also means
you must explicitly reestablish that phase's initial state.

---

## 18. Load the next request

```asm
LEA DX, ARROW_MSG
CALL PRINT_STRING
MOV BX, REQUESTS[SI]
MOV AX, CURRENT_HEAD
```

At this point:

```text
AX = current head
BX = next requested cylinder
```

`BX` keeps the request available while `AX` is overwritten with the distance.

The source does not modify or reorder `REQUESTS`; changing `SI` by two is what
selects the next arrival-order element.

---

## 19. Choose the subtraction direction

```asm
CMP AX, BX
JAE HEAD_IS_GREATER
```

Unsigned `JAE` means “jump if above or equal,” which corresponds here to:

```text
current head >= request
```

If that is false:

```asm
MOV AX, BX
SUB AX, CURRENT_HEAD
JMP ADD_MOVEMENT
```

computes `request − current head`.

Otherwise:

```asm
HEAD_IS_GREATER:
    SUB AX, BX
```

computes `current head − request`.

---

## 20. Equality is handled naturally

If current head and request are both 98, `JAE` takes the above-or-equal branch:

```text
AX = 98 − 98 = 0
```

The request is still serviced and printed, but adds zero movement.

Repeated requests are not removed from the queue. For:

```text
head: 50
requests: 50, 50, 70
```

the sequence is:

```text
50 -> 50 -> 50 -> 70
```

and total travel is `0 + 0 + 20 = 20`.

---

## 21. Accumulate and move the head

```asm
ADD TOTAL_MOVEMENT, AX
MOV CURRENT_HEAD, BX
MOV AX, BX
CALL PRINT_NUMBER
```

At entry, `AX` contains this leg's distance and `BX` contains its destination.

The operations mean:

```text
total += leg distance
current head = destination
print destination
```

Updating `CURRENT_HEAD` is essential. If every difference were calculated from
`INITIAL_HEAD`, the result would measure independent trips from the origin,
which is not FCFS head travel.

---

## 22. Advance and repeat

```asm
ADD SI, 2
LOOP FCFS_LOOP
```

`SI` advances one word. `LOOP` decrements `CX`, branching if the new count is
nonzero.

This is similar to the familiar 8085 pattern:

```text
advance pointer
decrement remaining count
jump if count not zero
```

8086 has a dedicated `LOOP` instruction using `CX`. It is not testing the zero
flag left by `ADD SI,2` or by printing.

---

## 23. A complete FCFS trace

Take the common example:

```text
initial head = 53
requests = 98, 183, 37, 122, 14, 124, 65, 67
```

| Step | Head before | Request | Distance | Running total |
| --- | --- | --- | --- | --- |
| 1 | 53 | 98 | 45 | 45 |
| 2 | 98 | 183 | 85 | 130 |
| 3 | 183 | 37 | 146 | 276 |
| 4 | 37 | 122 | 85 | 361 |
| 5 | 122 | 14 | 108 | 469 |
| 6 | 14 | 124 | 110 | 579 |
| 7 | 124 | 65 | 59 | 638 |
| 8 | 65 | 67 | 2 | 640 |

The final display is based on:

```text
Seek sequence: 53 -> 98 -> 183 -> 37 -> 122 -> 14 -> 124 -> 65 -> 67
Total head movement: 640 cylinders
```

This is a source-derived worked example, not a claim of a fresh interactive run.

## 24. Why a word total is sufficient

Every cylinder lies in `0..999`, so a single leg is at most 999.

There are at most ten requests, hence at most ten movement legs:

```text
maximum total <= 10 × 999 = 9990
```

An unsigned word can represent `0..65535`. Therefore `TOTAL_MOVEMENT DW 0` is
large enough for all accepted inputs.

The bound can be reached by starting at 0 and alternating requests between
999 and 0 for ten legs.

The implementation does not need multiword addition or an overflow handler
under these limits. Expanding the input range would require rechecking that
argument.

---

## 25. `READ_NUMBER`: preserve the caller's state

```asm
PUSH BX
PUSH CX
PUSH DX
PUSH SI
```

The routine uses these registers internally but restores them before returning.
`AX` is intentionally not preserved because it carries the parsed number.

This is why the outer request loop can keep:

```text
SI = next request-array offset
CX = remaining requests
```

across an input call, even though the conversion routine also loops with `CX`.

---

## 26. Read an echoed decimal line

```asm
MOV INPUT_BUFFER[1], 0
LEA DX, INPUT_BUFFER
MOV AH, 0AH
INT 21H
```

DOS supplies the count and typed bytes. The routine then emits line feed:

```asm
MOV DL, 0AH
MOV AH, 02H
INT 21H
```

This is the source's explicit display correction so the following prompt
advances to the next row in its DOSBox environment.

The byte `0AH` in `DL` is a character to print. `AH=02H` is the DOS function
number. They are separate uses of the value and register halves.

---

## 27. Reject an empty number

```asm
XOR CX, CX
MOV CL, INPUT_BUFFER[1]
CMP CX, 0
JE NUMBER_INVALID
LEA SI, INPUT_BUFFER[2]
XOR AX, AX
```

The input count determines how many characters to convert. The CR is not part
of that count, so no explicit terminator scan is needed.

`AX=0` initializes the decimal accumulator.

For digits `d0`, `d1`, `d2`, conversion repeatedly applies:

```text
new value = old value × 10 + next digit
```

---

## 28. Validate and convert one digit

```asm
MOV DL, [SI]
CMP DL, '0'
JB NUMBER_INVALID
CMP DL, '9'
JA NUMBER_INVALID
SUB DL, '0'
XOR DH, DH
MOV BX, DX
```

ASCII decimal digit codes are consecutive. Subtracting `'0'` converts the code
to the number `0..9`.

Clearing `DH` turns that byte into a word value in `DX`. Copying it to `BX`
protects the digit from the multiplication that follows.

Signs, spaces, letters, and punctuation are not accepted as numeric characters
by this routine. Leading zeroes are accepted.

---

## 29. Native multiplication builds the number

```asm
MOV DX, 10
MUL DX
ADD AX, BX
```

For a word operand, unsigned `MUL` means:

```text
DX:AX = old AX × operand
```

Here the operand is the old value of `DX`, set to 10. The instruction then
overwrites `DX` with the product's upper word.

That is exactly why the digit was moved to `BX` first.

With at most three input digits, the accumulator never exceeds 999, so the
upper product word remains zero throughout this conversion.

8085 has no native general multiply instruction. You would implement the
multiply-by-ten step with additions/shifts or another software routine.

---

## 30. Worked decimal conversion: `183`

| Character | Numeric digit in BX | AX before multiply | AX after multiply and add |
| --- | --- | --- | --- |
| `'1'` | 1 | 0 | `0×10+1 = 1` |
| `'8'` | 8 | 1 | `1×10+8 = 18` |
| `'3'` | 3 | 18 | `18×10+3 = 183` |

After each character:

```asm
INC SI
LOOP CONVERT_DIGIT
```

advances the character pointer and consumes one count.

The routine interprets decimal text. Input `183` is not assembled as a
hexadecimal literal; it arrives as three ASCII bytes at run time.

---

## 31. Return status through carry

After all digits succeed:

```asm
CLC
JMP READ_NUMBER_DONE
```

On invalid input:

```asm
NUMBER_INVALID:
    STC
```

Then saved registers are popped and the routine returns.

`POP` of an ordinary register and `RET` do not overwrite the carry flag, so
the caller can immediately use `JC`.

The stored input capacity bounds the number of characters returned by DOS.
There is no separate “too many digits” error in this helper; handling of keys
beyond the line-buffer capacity belongs to DOS's input service.

---

## 32. `PRINT_NUMBER`: special case zero

The printer saves `AX`, `BX`, `CX`, and `DX`.

```asm
CMP AX, 0
JNE DIVIDE_NUMBER
MOV DL, '0'
MOV AH, 02H
INT 21H
JMP PRINT_NUMBER_DONE
```

Zero needs an explicit output path because a “divide only while nonzero” loop
would otherwise produce no digits.

This matters for head position 0, request 0, and a schedule whose total movement
is 0.

---

## 33. Convert a nonzero word to decimal digits

```asm
XOR CX, CX
MOV BX, 10

DIVIDE_LOOP:
    XOR DX, DX
    DIV BX
    PUSH DX
    INC CX
    CMP AX, 0
    JNE DIVIDE_LOOP
```

Word `DIV BX` divides `DX:AX` by `BX`:

```text
AX = quotient
DX = remainder
```

Clearing `DX` before every division makes the dividend the current unsigned
word in `AX`, rather than an unintended larger 32-bit value.

Every remainder is a digit `0..9` and is pushed onto the CPU stack.

---

## 34. Why the digits go onto the stack

For 640:

```text
640 / 10 → quotient 64, remainder 0 → push 0
 64 / 10 → quotient  6, remainder 4 → push 4
  6 / 10 → quotient  0, remainder 6 → push 6
```

The remainders were found from right to left. A stack reverses that order:

```text
pop 6
pop 4
pop 0
```

The loop then adds `'0'` to each popped digit and prints its character:

```asm
POP DX
ADD DL, '0'
MOV AH, 02H
INT 21H
LOOP PRINT_DIGIT
```

`CX` tracks how many temporary digit words must be removed before restoring
the saved registers.

---

## 35. Printing preserves the scheduling loop

After all digits, the routine restores:

```asm
POP DX
POP CX
POP BX
POP AX
RET
```

Thus the FCFS loop's `CX` is not replaced by the printer's digit count, and its
`BX` request value is not replaced by the decimal divisor 10.

`SI` is not used by `PRINT_NUMBER`, so the array offset also survives.

This is an important general assembly habit: explain what each helper changes,
what it restores, and where its result is communicated.

---

## 36. `PRINT_STRING` and termination

```asm
PRINT_STRING PROC NEAR
    PUSH AX
    MOV AH, 09H
    INT 21H
    POP AX
    RET
PRINT_STRING ENDP
```

The string address is `DS:DX`, and `$` marks its end. `AX` is saved so printing
a label does not destroy an arithmetic value in that register.

After printing `TOTAL_MOVEMENT` and the units text, the program executes:

```asm
MOV AX, 4C00H
INT 21H
```

This terminates the DOS process with return status 0.

---

## 37. Register roles during the core loop

| Register / variable | Role |
| --- | --- |
| `SI` | Byte offset of the current request word |
| `CX` | Remaining request count |
| `BX` | Requested cylinder for this iteration |
| `AX` | Current head, then absolute leg distance, then printed request |
| `CURRENT_HEAD` | Last serviced cylinder, or initial head before first leg |
| `TOTAL_MOVEMENT` | Sum of completed leg distances |
| `INITIAL_HEAD` | Original starting position |

`AX` changes meaning within one iteration. This reuse is safe because the
destination cylinder remains in `BX` until it has been stored and printed.

---

## 38. High-level equivalent of the scheduling core

```c
current = initial_head;
total = 0;
print(current);

for (i = 0; i < request_count; i++) {
    request = requests[i];

    if (current >= request)
        distance = current - request;
    else
        distance = request - current;

    total += distance;
    current = request;
    print(" -> ");
    print(request);
}

print(total);
```

In the assembly array index, `SI=2*i` because the array elements are words.
The pseudocode's element index hides that byte-address calculation.

---

## 39. Why this is FCFS, not SSTF or SCAN

The only request-selection operation is:

```asm
MOV BX, REQUESTS[SI]
```

followed by increasing `SI` by two.

There is no search for the smallest distance, no sorted request list, and no
direction sweep toward the disk boundary.

For head 50 and requests 90, 51:

```text
FCFS order: 50 → 90 → 51
travel: 40 + 39 = 79
```

A nearest-request policy might choose 51 first, but this source deliberately
does not do so. Arrival order defines its behavior.

---

## 40. Boundary cases to understand

| Accepted input case | Expected calculation |
| --- | --- |
| One request equal to head | Total 0 |
| Head 0, one request 999 | Total 999 |
| Head 999, one request 0 | Total 999 |
| Repeated adjacent requests | Zero movement between repeats |
| All requests equal to initial head | Total 0 |
| Ten alternating extremes from opposite starting extreme | Total 9990 |

Count 0 and count 11 are rejected by the application-range checks. Empty input
or a nondigit causes the corresponding field to be retried.

The routine accepts leading zeroes in the returned line; `007` converts to 7.
It has no syntax for a minus sign, decimal fraction, or hexadecimal prefix.

---

## 41. What the output measures

The answer is total head movement in cylinders.

It is not elapsed time. The program does not model rotational latency,
controller delay, transfer time, or varying seek speed.

It also does not include a trip back to the initial head after the final
request. The schedule ends at the final requested cylinder.

These distinctions explain why the units message says `cylinders` and why the
total is simply a sum of absolute differences.

---

## 42. Time and storage costs

For `n` requests, the scheduling phase visits each element once:

```text
time: O(n)
extra scheduling state: O(1)
```

The program also stores the entered request list in its fixed ten-word array.
If generalized to an arbitrary list length, that list storage would be `O(n)`.

Printing and user input add their own character-processing work, but they do
not change the request-selection policy.

---

## 43. Connection to 8085

| Familiar 8085 concept | Corresponding source idea |
| --- | --- |
| Register-pair pointer | `SI` indexing a word array |
| Increment pointer to next data | `ADD SI,2` for two-byte elements |
| Compare, branch, subtract | `CMP`, `JAE`, `SUB` for absolute difference |
| Carry returned by a helper | `CLC` / `STC`, then caller `JC` |
| Preserve pairs across subroutines | Word `PUSH` / `POP` |
| Decimal arithmetic implemented in software | Native x86 `MUL` / `DIV` plus loops |

The algorithm transfers easily to 8085, but 16-bit subtraction would require
more explicit byte/carry handling there. The DOS interrupts are environment
services, not features shared by both CPUs.

---

## 44. The core facts to remember

The array order is the service order. The pointer advances two bytes because
each request is a word. The current head is updated after every leg, so the
next difference begins from the most recently serviced cylinder.

The comparison selects the nonnegative subtraction. The total fits a word
because there are at most ten legs, each at most 999.

Input parsing returns its number in `AX` and status in carry. The input and
printing helpers preserve the outer loop's count and pointer state.

---

## 45. Exam-ready explanation

The program accepts one to ten cylinder requests in arrival order and an
initial head position, with cylinder values from zero to 999. It stores the
requests as words and traverses them sequentially without sorting.

For each request it compares the current head with the requested cylinder,
subtracts the smaller from the larger to obtain the absolute distance, adds
that distance to a word accumulator, and updates the current head. It prints
the initial position, every serviced request, and the final total in cylinders.

DOS buffered input and repeated multiply-by-ten convert decimal text into
numbers. Repeated division by ten and a stack of remainders print the unsigned
results. Invalid input retries the current field, and saved registers preserve
the main loops across those helper calls.
