# MAZE4 Phone Controllers Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task.

**Goal:** Build an 8086 MASM maze race controlled by authenticated internet phones.
**Architecture:** MASM owns the authoritative game, lobby, COM1 protocol, and timers. A small Python standard-library bridge authenticates browsers and relays events; cloudflared supplies HTTPS reachability.
**Tech Stack:** Supplied dos-tools MASM/ML and LINK binaries, installed DOSBox 0.74-3, Python 3, vanilla HTML/CSS/JS, installed cloudflared.
**Spec:** `docs/superpowers/specs/2026-11-12-maze4-phone-design.md`

## Global Constraints

- Always use the binaries provided in `dos-tools/` for DOS assembly and linking.
- Up to eight players, cap `min(8, floor(F / 20), L)`, starts at equal BFS distance >=12.
- Two BIOS ticks per frame; warnings at path distances <5 and <3.
- MASM owns game rules, serial parsing, lobby admission, input expiry, disconnect/DNF, and rendering.
- HTTPS room password (12 random base32 characters), 256-bit per-player cookie, origin/CSRF checks.
- Public host controls are absent; PC keyboard controls lobby/start/reset/removal.
- ADB automates testing only; no ADB game traffic.
- Scratch, build intermediates, diagnostic logs, and downloads stay in `.scratch/`.

## Review Focus

- Reordered hold/release requests must not restart movement after release (Task 2/3).
- A removed player's reused slot must not accept the previous owner's credentials (Task 2).
- Serial partial/oversized/corrupt frames must resynchronize without hanging (Task 2/3).
- Internet or bridge loss must expire movement and preserve PC quit (Task 2/4).
- Browser reload and request retries must not allocate duplicate players (Task 3).
