```asm
; Question 1 - beginner version
; Read 10 bytes, calculate (value * 5) + 10, and transfer the results.

STACKSEG SEGMENT PARA STACK 'STACK'
    DW 128 DUP (?)
STACKSEG ENDS

DATASEG SEGMENT PARA PUBLIC 'DATA'
    TITLE_TEXT  DB 13,10,'QUESTION 1 - BLOCK TRANSFER',13,10,'$'
    PROMPT_TEXT DB 'Enter a byte (0-255): $'
    OUTPUT_TEXT DB 'Output: $'
    ERROR_TEXT  DB 'ERROR: enter a decimal number from 0 to 255.$'
    NEWLINE     DB 13,10,'$'

    ; DOS input buffer: maximum length, actual length, typed characters.
    INPUT_BUFFER DB 4,0,5 DUP (0)

    ORG 3000H
SOURCE_BYTES DB 10 DUP (?)

    ORG 4000H
DEST_BYTES DB 10 DUP (0)
DATASEG ENDS

CODESEG SEGMENT PARA PUBLIC 'CODE'
    ASSUME CS:CODESEG, DS:DATASEG, SS:STACKSEG

START:
    MOV AX, DATASEG
    MOV DS, AX

    LEA DX, TITLE_TEXT
    CALL PRINT_STRING

    ; Read 10 decimal byte values into DS:3000H.
    MOV DI, 3000H
    MOV CX, 10

INPUT_LOOP:
    LEA DX, PROMPT_TEXT
    CALL PRINT_STRING
    CALL READ_BYTE
    JNC INPUT_OK
    JMP BAD_INPUT

INPUT_OK:
    MOV [DI], AL
    INC DI
    CALL PRINT_NEWLINE
    LOOP INPUT_LOOP

    ; This is the main part required by the question.
    MOV SI, 3000H
    MOV DI, 4000H
    MOV CX, 10

TRANSFER_LOOP:
    MOV AL, [SI]
    MOV BL, 5
    MUL BL
    ADD AX, 10
    MOV [DI], AL

    INC SI
    INC DI
    LOOP TRANSFER_LOOP

    ; Print the bytes stored at DS:4000H.
    LEA DX, OUTPUT_TEXT
    CALL PRINT_STRING
    MOV SI, 4000H
    MOV CX, 10

OUTPUT_LOOP:
    XOR AX, AX
    MOV AL, [SI]
    CALL PRINT_BYTE

    MOV DL, ' '
    MOV AH, 02H
    INT 21H

    INC SI
    LOOP OUTPUT_LOOP
    CALL PRINT_NEWLINE
    JMP EXIT_OK

BAD_INPUT:
    LEA DX, ERROR_TEXT
    CALL PRINT_STRING
    CALL PRINT_NEWLINE
    MOV AX, 4C01H
    INT 21H

EXIT_OK:
    MOV AX, 4C00H
    INT 21H

; Read one decimal number from 0 through 255.
; Return: AL = byte and CF = 0, or CF = 1 for invalid input.
READ_BYTE PROC NEAR
    PUSH BX
    PUSH CX
    PUSH DX
    PUSH SI

    LEA DX, INPUT_BUFFER
    MOV AH, 0AH
    INT 21H

    MOV CL, INPUT_BUFFER[1]
    XOR CH, CH
    JCXZ RB_INVALID
    CMP CX, 3
    JA RB_INVALID

    LEA SI, INPUT_BUFFER[2]
    XOR BX, BX

RB_NEXT_DIGIT:
    MOV AL, [SI]
    CMP AL, '0'
    JB RB_INVALID
    CMP AL, '9'
    JA RB_INVALID

    MOV DL, AL
    SUB DL, '0'
    XOR DH, DH

    ; New value = old value * 10 + new digit.
    MOV AX, BX
    SHL AX, 1
    MOV BX, AX
    SHL AX, 1
    SHL AX, 1
    ADD AX, BX
    ADD AX, DX

    CMP AX, 255
    JA RB_INVALID
    MOV BX, AX
    INC SI
    LOOP RB_NEXT_DIGIT

    MOV AX, BX
    CLC
    JMP SHORT RB_RETURN

RB_INVALID:
    STC

RB_RETURN:
    POP SI
    POP DX
    POP CX
    POP BX
    RET
READ_BYTE ENDP

; Print the unsigned byte in AX as decimal.
PRINT_BYTE PROC NEAR
    PUSH AX
    PUSH BX
    PUSH CX
    PUSH DX

    XOR CX, CX
    MOV BX, 10

PB_DIVIDE:
    XOR DX, DX
    DIV BX
    PUSH DX
    INC CX
    OR AX, AX
    JNZ PB_DIVIDE

PB_PRINT:
    POP DX
    ADD DL, '0'
    MOV AH, 02H
    INT 21H
    LOOP PB_PRINT

    POP DX
    POP CX
    POP BX
    POP AX
    RET
PRINT_BYTE ENDP

PRINT_STRING PROC NEAR
    MOV AH, 09H
    INT 21H
    RET
PRINT_STRING ENDP

PRINT_NEWLINE PROC NEAR
    LEA DX, NEWLINE
    CALL PRINT_STRING
    RET
PRINT_NEWLINE ENDP

CODESEG ENDS
END START
```

Perfect—this is a very good first MASM program because it introduces almost everything you need: **segments, 16-bit registers, memory addressing, loops, procedures, DOS interrupts, stack usage, multiplication, and input/output**. 🚀

Since you know 8085, I’ll constantly connect x86/MASM ideas to their closest 8085 equivalents.

The program’s actual task is simple:

> Read 10 byte values → store them starting at `DS:3000H` → calculate `(value × 5) + 10` for each → store the results starting at `DS:4000H` → print those results.

There is extra code only to make keyboard input/output convenient.

# 1. First understand what MASM actually is

**MASM = Microsoft Macro Assembler.**

It is an assembler for the **x86 family** of processors.

Your 8085 code might look like:

```asm
MVI A, 05H
MOV B, A
ADD B
```

In 8086 MASM, similar ideas look like:

```asm
MOV AL, 05H
MOV BL, AL
ADD AL, BL
```

The biggest immediate difference is that 8086 has **many more registers** and most of them are **16-bit**.

---

# 2. Important 8086 registers

The first thing you need to learn is this register structure.

```text
AX = AH + AL
BX = BH + BL
CX = CH + CL
DX = DH + DL
```

Each complete register is 16-bit:

```text
AX = 16 bits
```

but it can be split into two 8-bit registers:

```text
        AX
┌───────────────────┐
│    AH    │   AL   │
│  8 bits  │ 8 bits │
└───────────────────┘
```

For example:

```asm
MOV AX, 1234H
```

means:

```text
AX = 1234H
AH = 12H
AL = 34H
```

This is very important.

### Rough 8085 comparison

| 8085 | 8086 |
|---|---|
| `A` | often `AL` or `AX` |
| `B`, `C` | `BX`, `CX`, etc. |
| `HL` memory pointer | often `SI` or `DI` |
| `SP` | `SP` |
| flags | FLAGS register |

8086 isn't exactly equivalent, but this mental mapping will help initially.

---

# 3. Overall structure of this program

Your program has three major sections:

```asm
STACKSEG
DATASEG
CODESEG
```

Think of them as:

```text
STACKSEG → stack memory
DATASEG  → variables/data
CODESEG  → instructions/program
```

In a simple 8085 program, code and data often just live at particular memory addresses.

8086 introduces **segments**, which is one of the biggest differences.

# 4. Stack segment

```asm
STACKSEG SEGMENT PARA STACK 'STACK'
    DW 128 DUP (?)
STACKSEG ENDS
```

Let's break it down.

### `STACKSEG SEGMENT`

Starts a segment named:

```text
STACKSEG
```

The name itself is chosen by the programmer.

---

### `PARA`

Means the segment should start on a **paragraph boundary**.

In 8086 terminology:

```text
1 paragraph = 16 bytes
```

Don't worry about this yet. MASM/DOS handles it.

---

### `STACK`

Tells the assembler/linker that this segment is intended to be the program's stack.

---

### `'STACK'`

This is the segment's **class name**.

Again, you don't need to worry much about this yet.

---

## `DW 128 DUP (?)`

Now this is useful.

### `DW`

Means:

```text
Define Word
```

One word on 8086 is:

```text
16 bits = 2 bytes
```

So:

```asm
DW 128
```

would define one 16-bit value containing `128`.

But that's not what's happening here.

---

### `DUP`

Means repeat.

```asm
128 DUP (?)
```

means:

> reserve 128 elements.

And each element is a word because we used `DW`.

Therefore:

```text
128 × 2 bytes = 256 bytes
```

of stack memory are reserved.

---

### `?`

Means:

> don't initialize this memory.

So:

```asm
DW 128 DUP (?)
```

means:

> Reserve 128 uninitialized words = 256 bytes.

---


# 8. Input buffer

Now:

```asm

```

This looks strange initially.

It creates bytes like:

```text
4
0
0
0
0
0
0
```

DOS keyboard input function `0AH` expects a special buffer structure.

The memory layout becomes:

```text
INPUT_BUFFER + 0 → maximum number of characters
INPUT_BUFFER + 1 → number actually entered
INPUT_BUFFER + 2 → first typed character
INPUT_BUFFER + 3 → second typed character
...
```

So:

```asm

```

means roughly:

```text

actual length = initially 0
space reserved for typed characters
```

# 9. `ORG 3000H`

Now something very important:

```asm
ORG 3000H
SOURCE_BYTES DB 10 DUP (?)
```

`ORG` means:

> Set the assembler's current offset to this address.

So:

```asm
ORG 3000H
```

means the following variable starts at offset:

```text
3000H
```

Therefore:

```asm
SOURCE_BYTES DB 10 DUP (?)
```

allocates:

```text
10 bytes
```

starting from:

```text
DS:3000H
```

So:

```text
DS:3000H
DS:3001H
DS:3002H
...
DS:3009H
```

hold the 10 input bytes.

This is very similar conceptually to being told in 8085:

> Store 10 bytes starting at memory location 3000H.

Similarly:

```asm

DEST_BYTES DB 10 DUP (0)
```

allocates ten bytes starting from:


So the calculated answers will occupy:

```text
DS:4000H
DS:4001H

DS:4009H
```

# 12. `ASSUME`

```asm
ASSUME CS:CODESEG, DS:DATASEG, SS:STACKSEG
```

This is important but often misunderstood.

It tells **MASM**:

```text
CS corresponds to CODESEG
DS corresponds to DATASEG
SS corresponds to STACKSEG
```

But:

> `ASSUME` does not actually load the CPU registers.

It's only information for the assembler.

That is why this is still necessary:

```asm
MOV AX, DATASEG
MOV DS, AX
```

# 13. What are `CS`, `DS`, and `SS`?

8086 uses segment registers.

The important ones are:

```text
CS = Code Segment
DS = Data Segment
SS = Stack Segment
ES = Extra Segment
```

You can think of them as telling the processor **which region of memory you're working in**.

For now, remember:

```text
CS → instructions
DS → variables/data
SS → stack
```

# 15. Initializing DS

Now:

```asm
MOV AX, DATASEG
MOV DS, AX
```

This is one of the first things you'll see in almost every old DOS MASM program.

Why?

Because `DS` must point to your data segment.

Conceptually:

```text
AX ← address of DATASEG
DS ← AX
```

Why use AX as the middleman?

Because you normally cannot write:

```asm
MOV DS, DATASEG
```

So we do:

```asm
MOV AX, DATASEG
MOV DS, AX
```

After this, instructions using data variables know where to find them.

# 16. Printing the title

```asm
LEA DX, TITLE_TEXT
CALL PRINT_STRING
```

This introduces two major ideas.

---

## `LEA`

`LEA` means:

```text
Load Effective Address
```

So:

```asm
LEA DX, TITLE_TEXT
```

does **not** load the contents of the string.

It loads the **address** of the string.

Conceptually:

```text
DX ← address of TITLE_TEXT
```

Compare:

```asm
MOV AL, [SI]
```

which loads the actual data stored in memory.

Whereas:

```asm
LEA DX, TITLE_TEXT
```

loads where that data is located.

means:

Similar to an 8085:


```asm

```

and execution returns here.

So your knowledge transfers directly. 👍


Here:

means:

Same concept here.

# 28. `MUL BL`

This is a new and important x86 instruction.

```asm
MUL BL
```

means:

```text
AL × BL → AX
```

Notice something special:

For an **8-bit multiplication**, x86 implicitly uses:

```text
AL
```

as one operand.

So:

```asm
MUL BL
```

does:

```text
AX = AL × BL
```

Example:

```text
AL = 20
BL = 5

20 × 5 = 100
AX = 100
```

But why AX instead of AL?

Because:

```text
255 × 255 = 65025
```

which cannot fit in 8 bits.

So the result is 16-bit.

---

# 29. Add 10

```asm
ADD AX, 10
```

Now:

```text
AX = AL_original × 5 + 10
```

Example:

```text
input = 20

20 × 5 = 100
100 + 10 = 110
```

So:

```text
AX = 110
AL = low 8 bits of 110
```

# 30. Store only AL

```asm
MOV [DI], AL
```

This stores only the lower byte.

So:

```text
DS:4000H ← AL
```

⚠️ This means if the result exceeds `255`, only the lowest 8 bits are saved.

For example:

```text
input = 100

100 × 5 + 10
= 510
```

510 decimal is:

```text
01FEH
```

So:

```text
AX = 01FEH
AH = 01H
AL = FEH
```

Only:

```text
FEH = 254
```

gets stored.

This is **8-bit overflow/wraparound behavior**.

That's an important detail in this program.

So:

```text

    value = source[i]
```

# 32. The entire core in 8085-like thinking

This part:


```text

    A-like register = [source]
    multiply by 5
    add 10
    [destination] = result

    source++
    destination++
    counter--
```

That's the part you should understand first for the actual assignment.

# 37. Why `INT 21H`?

In DOS, your assembly program does not directly know how to:

```text
print text
read keyboard input
terminate program
```

Instead, it asks DOS.

This is similar conceptually to an operating-system API.

You put parameters into registers and execute:

```asm
INT 21H
```

DOS examines `AH` and performs the requested service.

Some services used here are:

| AH | DOS service |
|---|---|
| `02H` | print one character |
| `09H` | print `$`-terminated string |
| `0AH` | buffered keyboard input |
| `4CH` | terminate program |

You'll see these constantly in DOS MASM programs.

```text

AL = 01H
```

```text
AH = 4CH → terminate program
AL = 01H → exit code 1
```

For successful termination:

```asm
MOV AX, 4C00H
INT 21H
```

means:

```text

AL = 00H
```

so:

```text
exit successfully
```

# 40. What does `NEAR` mean?


# 41. Why all the `PUSH` instructions?

At the start of `READ_BYTE`:

```asm
PUSH BX
PUSH CX
PUSH DX
PUSH SI
```

The procedure is going to modify these registers.

But the caller may be using them.

So before changing them, we save their old values on the stack.

Then before returning:

```asm
POP SI
POP DX
POP CX
POP BX
```

restores them.

Notice the reverse order.

If we push:

```text
BX
CX
DX
SI
```

we must pop:

```text
SI
DX
CX
BX
```

because the stack is:

```text
LIFO
Last In, First Out
```

This works exactly like the stack concept you already know from 8085.

Now:

```asm
LEA DX, INPUT_BUFFER
MOV AH, 0AH
INT 21H
```

DOS function:

```text

```

means:

> Buffered keyboard input.

Therefore:

```asm

```

passes that buffer to DOS.


```text

INPUT_BUFFER[1] = 3

INPUT_BUFFER[3] = '2'
```

# 43. Getting number of typed characters



makes:

```text

```

# 47. Validate each digit

# 48. Convert ASCII digit to number


Therefore:

# 50. The multiplication-by-10 trick

Now this part looks intimidating:

```asm
MOV AX, BX
SHL AX, 1
MOV BX, AX
SHL AX, 1
SHL AX, 1
ADD AX, BX
ADD AX, DX
```

But it's just calculating:

```text
old_value × 10 + digit
```

Let's decode it.

Suppose:

```text
BX = old value
```

First:

```asm
MOV AX, BX
```

so:

```text
AX = old value
```

Then:

```asm
SHL AX, 1
```

A left shift by one multiplies by 2.

So:

```text
AX = old × 2
```

Then:

```asm
MOV BX, AX
```

Now:

```text
BX = old × 2
```

Then:

```asm
SHL AX, 1
SHL AX, 1
```

Two more left shifts mean:

```text
old × 2 × 2 × 2
= old × 8
```

So now:

```text
AX = old × 8
BX = old × 2
```

Then:

```asm
ADD AX, BX
```

gives:

```text
old × 8 + old × 2
= old × 10
```

Then:

```asm
ADD AX, DX
```

adds the new digit.

So:

```text
AX = old × 10 + digit
```

Very clever.

# 51. Why use `SHL`?

`SHL` means:

```text
Shift Left
```

Example:

```text
00000101 = 5
```

Shift left by one:

```text
00001010 = 10
```

So generally:

```text
x << 1 = x × 2
```

unless overflow occurs.

This is something you'll see often in assembly.




```text

2
```

Exactly what we need.

# 66. What you should memorize from this problem

Don't try to memorize all of `READ_BYTE` and `PRINT_BYTE` yet.

For your **first MASM problem**, these are the essential concepts:

- `AX`, `BX`, `CX`, `DX` are 16-bit registers; `AX` can be split into `AH`/`AL`, etc.
- `SI` and `DI` are often used as memory pointers.
- `[SI]` means **memory whose offset is stored in SI**.
- `DS` points to your program's data segment.
- `MOV AX, DATASEG / MOV DS, AX` initializes the data segment.
- `CX + LOOP` is a convenient counter loop.
- `MUL BL` performs `AL × BL → AX`.
- `LEA DX, variable` gets a variable's address.
- `CALL` and `RET` work much like 8085.
- `PUSH`/`POP` use the stack.
- `INT 21H` requests a DOS service.
- `PROC`/`ENDP` define procedures.

# 68. Finally, the actual algorithm you should be able to explain in an exam

The core required part is only this:

```asm
MOV SI, 3000H
MOV DI, 4000H
MOV CX, 10

TRANSFER_LOOP:
    MOV AL, [SI]
    MOV BL, 5
    MUL BL
    ADD AX, 10
    MOV [DI], AL

    INC SI
    INC DI
    LOOP TRANSFER_LOOP
```

Read it in plain English:

> SI points to the source array at `3000H`, DI points to the destination array at `4000H`, and CX is initialized to 10. Each source byte is loaded into AL, multiplied by 5 using `MUL BL`, and 10 is added to the 16-bit result in AX. The low byte of the result is then stored in the destination array. SI and DI are incremented to move to the next source and destination bytes, and `LOOP` repeats the process ten times.

If you understand **this block deeply**, you've already learned the central MASM concepts required by Question 1. The input and printing procedures are supporting infrastructure, not the heart of the assignment.
